## 2026-05-31

### 1. 精读引言部分

**问：** 带我精读引言部分。

**答：**

可以。我们把 `nature16961.pdf` 的引言精读到 `Supervised learning of policy networks` 之前。这部分的任务是回答一个问题：**AlphaGo 为什么需要把深度神经网络和树搜索结合起来？**

**1. 摘要先给出整篇论文答案**

摘要开头说，围棋长期被认为是 AI 中最难的经典棋类之一，原因有两个：

- 搜索空间巨大。
- 很难准确评估一个局面和一个落子的好坏。

AlphaGo 的核心方案是：

```text
policy network：选择候选落子
value network：评估棋盘局面
MCTS：把候选落子和局面评估结合成搜索
```

这里要注意：论文不是说“神经网络直接下棋就够了”，而是说神经网络负责给搜索提供更强的判断力。

**2. 第一段：把围棋放进“完美信息博弈”框架**

论文先讲一个理论概念：所有完美信息游戏都有一个最优价值函数 `v*(s)`。

简单说：

```text
s = 当前局面
v*(s) = 如果双方都完美下棋，当前局面最终是赢还是输
```

如果我们真的知道 `v*(s)`，围棋就被解决了。每一步只要选能让自己最终赢的走法即可。

问题是：我们不知道 `v*(s)`，只能通过搜索近似它。

**3. 第二段：为什么穷举搜索不可行**

论文用一个公式说明搜索难度：

```text
可能变化数量约为 b^d
```

其中：

- `b` 是每个局面的平均合法走法数。
- `d` 是一盘棋的平均长度。

论文给出对比：

```text
国际象棋：b ≈ 35, d ≈ 80
围棋：b ≈ 250, d ≈ 150
```

所以围棋不是“多一点难”，而是组合爆炸极其严重。完整搜索不现实。

这里的理解重点：**AlphaGo 的目标不是穷举，而是聪明地减少搜索。**

**4. 第三段：减少搜索的两个原则**

论文提出两个通用办法。

第一个办法：减少搜索深度。

也就是不一直搜到终局，而是在中途停下来，用一个价值函数评估局面：

```text
不要完整搜索到棋局结束
而是在某个局面 s 停下
用 v(s) 估计这个局面好不好
```

这就是 value network 要解决的问题。

第二个办法：减少搜索宽度。

也就是不要平等考虑所有合法落子，而是用一个策略 `p(a|s)` 给每个动作一个概率：

```text
p(a|s) = 在局面 s 下，选择动作 a 的概率
```

这就是 policy network 要解决的问题。

所以，引言这里已经把 AlphaGo 的两个神经网络角色讲清楚了：

```text
value network：减少深度
policy network：减少宽度
```

**5. 第四段：传统 MCTS 的位置**

接着论文介绍 MCTS。

MCTS 的思想是：通过大量模拟对局估计每个走法的价值。模拟越多，搜索树越可靠。

传统围棋程序已经大量使用 MCTS，并且会加入一些人工设计的策略或特征。但问题是：

- rollout 的随机模拟质量有限。
- 旧方法里的策略和值函数通常比较浅。
- 很多依赖人工特征，表达能力不足。

论文要表达的是：MCTS 本身有用，但它缺少强大的局面理解能力。

**6. 第五段：为什么引入深度卷积网络**

论文随后转向深度学习。

围棋棋盘可以看作一个 `19 × 19` 的图像。卷积神经网络可以从局部棋形逐层构造更抽象的表示。

这一步很关键。论文把围棋问题转化成类似视觉问题：

```text
棋盘状态 -> 多通道 19x19 图像
卷积网络 -> 提取棋形、气、连接、攻杀等模式
输出 -> 落子概率或胜率
```

所以 AlphaGo 不是手写大量围棋知识，而是让深度网络从棋谱和自我对弈中学习表示。

**7. 最后一段：训练管线总览**

引言最后给出整篇论文的训练流程：

```text
1. 用人类高手棋谱训练 SL policy network
2. 训练 fast rollout policy
3. 用自我对弈强化学习得到 RL policy network
4. 用自我对弈数据训练 value network
5. 在实战中用 MCTS 结合 policy + value
```

这一段是全文路线图。后面的正文只是逐个展开这五件事。

**你现在应该抓住的核心**

引言的逻辑可以压缩成一句话：

```text
围棋搜索空间太大，所以 AlphaGo 用 policy network 缩小候选落子范围，用 value network 评估中间局面，再用 MCTS 把二者结合起来做强搜索。
```

读完引言后，先确认你能回答这三个问题：

1. 为什么围棋不能靠穷举搜索？
2. policy network 和 value network 分别减少了搜索的哪一部分？
3. 为什么 AlphaGo 不是单纯的神经网络程序，而是神经网络 + MCTS？

### 2. 关于卷积的直观理解

**问：** 这里的卷积是不是可以理解为范围较大的棋盘局部？比如5 x 5 ？

**答：**

可以这样理解，但要更精确一点：

**卷积就是在棋盘上滑动一个局部观察窗口。**

在 AlphaGo 这篇论文里，policy network 的结构是：

```text
输入：19 × 19 × 48 特征平面

第 1 层卷积：5 × 5 卷积核
第 2-12 层卷积：3 × 3 卷积核
最后一层：1 × 1 卷积，输出每个交叉点的落子概率
```

所以你说的 **“比如 5×5 的棋盘局部”**，对第一层卷积是对的。

但还要注意两点：

1. **卷积核看的不是单纯黑白棋子**

   它看的输入是 `19 × 19 × 48`，也就是每个位置有很多特征，比如：

   - 当前玩家棋子
   - 对手棋子
   - 空点
   - 气数
   - 是否能提子
   - 是否自杀
   - 最近几手
   - 征子相关特征

   所以一个 `5 × 5` 卷积核实际看的是：

   ```text
   5 × 5 × 48
   ```

2. **深层卷积会看到更大的范围**

   第一层看 `5×5`，第二层虽然是 `3×3`，但它看的已经不是原始棋盘，而是第一层提取出的局部模式。

   感受野会逐层扩大：

   ```text
   第 1 层：看到 5×5
   第 2 层：约看到 7×7
   第 3 层：约看到 9×9
   ...
   第 12 层：理论上已经能覆盖整个 19×19 棋盘
   ```

所以更准确地说：

```text
浅层卷积学习局部棋形；
深层卷积把局部棋形组合成更大范围的棋盘判断。
```

比如：

```text
浅层：这个局部像不像虎口、断点、连接、气紧
中层：这一片棋是否被攻击、是否有眼形、是否可征
深层：整块棋的生死、厚薄、全局方向
```

但这些不是程序员手写进去的，而是网络从棋谱和训练过程中学出来的。卷积的作用是给网络一个合适的结构假设：**围棋中很多判断来自局部棋形，而局部棋形可以出现在棋盘任何位置。**

### 3. 关于卷积层配置的依据

**问：** 卷积层的配置是人为的还是有有一定依据的？

**答：**

两者都有：**是人为设计的超参数，但不是随便拍脑袋**。

在 AlphaGo 这篇论文里，卷积层配置大致是：

```text
policy network:
输入：19 × 19 × 48
第 1 层：5 × 5 卷积
第 2-12 层：3 × 3 卷积
最后：1 × 1 卷积 + softmax
```

这些配置的依据主要有几类。

**1. 围棋棋盘天然适合卷积**

围棋很多模式是局部的，而且可以平移：

```text
角上的小飞
边上的拆边
局部断点
气数紧张
连接与切断
征子局部形状
```

同一种棋形出现在棋盘左上、右下，含义往往相似。所以用共享参数的卷积层很自然。

**2. 小卷积核更适合逐层组合**

`3×3`、`5×5` 这种小卷积核在视觉任务中很常见。原因是：

- 参数量少。
- 计算量可控。
- 多层堆叠后感受野会变大。
- 每层加入非线性，表达能力更强。

比如连续堆叠 `3×3` 卷积，可以逐渐从小棋形组合出大棋形。

**3. 第一层用 5×5 有局部棋形直觉**

第一层直接看原始棋盘特征。用 `5×5` 可以一次看到一个稍大的局部棋形区域，比 `3×3` 更容易捕捉围棋中常见的局部关系。

后面用 `3×3`，则是在已经提取出的模式上继续组合。

**4. 层数和通道数是实验权衡**

论文里测试了不同 filter 数量，比如：

```text
128 / 192 / 256 / 384 filters
```

更大网络通常更强，但更慢。AlphaGo 实战版本用了 `192 filters`，这是棋力、速度、GPU 计算之间的折中。

因为 MCTS 要反复调用神经网络，网络不能无限大。否则单次评估很强，但搜索次数下降，整体未必更强。

**5. 当时也借鉴了计算机视觉经验**

AlphaGo 不是从零发明 CNN。它借鉴了图像识别中成熟的卷积网络经验：

```text
局部连接
参数共享
多层非线性
小卷积核堆叠
```

围棋棋盘被表示成 `19×19` 的多通道图像，所以这些经验可以迁移过来。

**一句话总结**

卷积层配置是人工选择的超参数，但依据来自三方面：

```text
围棋的局部棋形结构
CNN 在图像任务中的成功经验
实际训练速度和棋力实验结果
```

所以它不是理论上唯一正确的配置，而是一个经过工程实验验证的合理选择。

### 5. 阅读 Section 1：监督学习策略网络

**问：** 带我读section 1

**答：**

这里按论文第一正文小节 `Supervised learning of policy networks` 来读。如果你说的 section 1 是别的编号，可以再指定。

这一节要回答的问题是：**AlphaGo 如何先学会“像高手一样落子”？**

**1. 这一节的位置**

引言最后给出了完整训练管线：

```text
人类棋谱 -> 监督学习策略网络 -> 强化学习策略网络 -> 价值网络 -> MCTS
```

Section 1 讲的是第一步：用人类高手棋谱训练一个策略网络 `pσ(a|s)`。

这里：

```text
s = 当前棋盘局面
a = 一个可能落子
pσ(a|s) = 网络认为高手在局面 s 下选择落子 a 的概率
```

**2. 训练目标**

论文说，策略网络通过监督学习预测专家落子。

也就是给网络很多样本：

```text
输入：棋盘局面 s
标签：人类高手实际下的那一步 a
```

训练目标是让网络给高手那一步更高概率。

公式是：

```text
Δσ ∝ ∂ log pσ(a|s) / ∂σ
```

直观解释：

```text
如果高手在局面 s 下下了 a，
就调整网络参数 σ，
让 pσ(a|s) 变大。
```

这本质上是一个分类问题：在当前局面下，从所有可能落点中预测专家选择哪一个。

**3. 网络输入与输出**

输入不是单纯黑白棋盘，而是棋盘特征表示。论文在正文中简单说是 board state，Methods 中展开为 `19 × 19 × 48` 特征平面。

输出是所有合法落子的概率分布，可以理解为一张 `19 × 19` 的概率图：

```text
每个交叉点一个概率
概率越高，表示网络越认为高手会下在那里
```

**4. 网络结构**

论文这里说策略网络是卷积网络：

```text
卷积层 + ReLU
卷积层 + ReLU
...
最后 softmax 输出落子概率
```

它训练的是一个 13 层 policy network。更细的结构在 Methods：

```text
第 1 层：5×5 卷积
第 2-12 层：3×3 卷积
最后：1×1 卷积 + softmax
```

这一结构的意义是：从局部棋形开始，逐层组合成更大范围的棋盘判断。

**5. 数据与结果**

论文正文给出的结果：

- 使用 KGS Go Server 的约 3000 万个局面训练。
- 13 层策略网络在测试集上预测专家落子准确率达到 `57.0%`。
- 只用原始棋盘位置和历史信息时也有 `55.7%`。
- 当时其他研究组的最好结果约为 `44.4%`。

注意这个准确率不是胜率，而是：

```text
网络预测的第一选择 == 人类高手实际落子
```

围棋中很多局面有多个合理选择，所以 57% 已经很高。

**6. 为什么只模仿高手还不够**

监督学习策略网络的优点：

- 学得快。
- 训练信号明确。
- 能迅速获得接近高手的落子直觉。

但它也有局限：

- 它学的是“人类会怎么下”，不是直接优化“怎样赢”。
- 人类棋谱有水平和风格上限。
- 它单独下棋时没有搜索，容易漏算复杂战斗。

所以后面还要做两件事：

```text
用强化学习让策略网络从“模仿高手”变成“追求胜利”
用 MCTS 搜索提升最终落子质量
```

**7. Fast rollout policy**

这一节最后还提到另一个策略：`pπ(a|s)`，也就是 fast rollout policy。

它比深度策略网络弱很多，但速度极快：

```text
深度 policy network：更准，但一次评估约毫秒级
fast rollout policy：较弱，但约微秒级
```

论文结果：

- rollout policy 预测专家落子的准确率是 `24.2%`。
- 选择一步只需约 `2 μs`。
- 深度策略网络约 `3 ms`。

它的用途不是直接下棋，而是在 MCTS 中快速模拟到终局。

**本节核心**

Section 1 的核心可以压缩成一句话：

```text
AlphaGo 先把高手棋谱当作监督学习数据，训练一个卷积策略网络，让它在给定棋盘局面时输出接近高手直觉的落子概率。
```

这一节读完，你需要记住三个点：

1. `pσ(a|s)` 是模仿人类高手的策略网络。
2. 训练目标是提高人类实际落子的概率。
3. 这个网络提供了 AlphaGo 最初的棋感，但还不是最终的 AlphaGo。

### 6. 监督学习标签是否唯一

**问：** 给定局面，标签是唯一的么？因为人类棋手的下法很可能不唯一。

**答：**

在训练数据里，**标签通常是唯一的**；但在围棋意义上，**合理下法当然不唯一**。

对一个训练样本来说，数据长这样：

```text
输入：某个真实棋局中的局面 s
标签：这盘棋里高手实际下的那一步 a
```

所以监督学习把它当成一个单标签分类问题：

```text
在 19×19 个落点中，把实际落子 a 当作正确答案
```

但这只是数据记录的“实际选择”，不是说其他落子都一定错。

更准确地说：

```text
论文中的监督学习目标：
学习人类棋手在该局面下实际选择的落子分布

不是：
学习所有客观上同样好的落子集合
```

这会带来一个局限：如果某个局面有两个都很好的选择 A 和 B，而棋谱里人类下了 A，那么训练会提高 A 的概率；如果网络预测 B，它在监督学习准确率上会被算错，即使 B 可能也是好棋。

这也是为什么 `57%` 的 top-1 准确率已经很高。围棋不是图像分类那种“猫就是猫、狗就是狗”的唯一答案问题。很多局面存在多个风格不同但都合理的下法。

不过训练目标不是只学一个硬答案。softmax 输出的是一个概率分布：

```text
pσ(a|s)
```

理想情况下，网络会给多个合理点较高概率，只是训练样本中被观察到的那一步获得最直接的正反馈。

这也解释了后续为什么还需要强化学习和 MCTS：

```text
监督学习：学“高手通常怎么下”
强化学习：学“怎样更容易赢”
MCTS：在多个候选好点中进一步搜索验证
```

所以你的直觉是对的：**人类下法不唯一；论文只是把每个棋谱局面中实际发生的那一步作为监督标签。**

### 7. 人类棋谱中的坏棋会不会误导训练

**问：** 那如果人类棋手下了臭棋，训练的方向不就反了？

**答：**

会的。从单个样本看，如果高手在某个局面真的下了一步坏棋，监督学习确实会把这一步当作正标签，提高它的概率。这就是监督学习中的**标签噪声**问题。

但在 AlphaGo 里，这个问题被几层机制缓解了：

1. **数据来自高水平棋手**

   论文用的是 KGS 6 到 9 段棋手的棋谱。不是说这些棋手不会下错，但坏棋比例比普通棋谱低很多。

2. **数据量很大**

   训练集有约 3000 万个局面。单个坏样本会产生错误梯度，但大量样本的平均效果仍然会学习到常见的强棋模式。

3. **网络学的是统计倾向，不是死记每一手**

   如果某类局面里大多数高手都倾向于好点，少量坏棋只是噪声。模型不会因为一个样本就固定认为某个局部永远该那样下。

4. **监督学习只是初始化**

   AlphaGo 后面还有强化学习。强化学习的目标不是“像人类”，而是“赢棋”。如果某些人类习惯或坏棋降低胜率，自我对弈会把策略往更能赢的方向推。

5. **最终落子还经过 MCTS**

   实战时不是直接采用监督学习网络最大概率落子，而是用 MCTS 搜索。policy network 只是提供候选方向和先验概率，MCTS 会结合价值网络和 rollout 进一步检验。

所以你说的方向是对的：**监督学习确实可能从人类坏棋中学到错误信号。** 这也是为什么 AlphaGo 没停在监督学习，而是继续做强化学习和搜索。

可以把三层作用理解成：

```text
监督学习：给一个接近高手的起点
强化学习：纠正“像人但未必赢”的地方
MCTS：每一步再用搜索验证
```

因此，人类臭棋会造成噪声，但不会决定最终系统的方向。

### 8. 阅读 Section 2：强化学习策略网络

**问：** 继续带我读section 2

**答：**

这里读论文第二个正文小节：`Reinforcement learning of policy networks`。

这一节要回答的问题是：**AlphaGo 如何从“模仿高手”进一步变成“优化胜率”？**

**1. Section 2 的位置**

上一节训练的是监督学习策略网络：

```text
pσ(a|s)：模仿人类高手落子
```

这一节在它的基础上继续训练：

```text
pρ(a|s)：通过自我对弈强化学习得到的策略网络
```

论文里说，RL policy network 和 SL policy network 结构相同，初始参数也相同：

```text
ρ = σ
```

也就是说，强化学习不是从随机网络开始，而是从“已经会模仿高手”的网络开始。

**2. 为什么要做强化学习**

监督学习的目标是：

```text
最大化人类实际落子的概率
```

但这不等于最大化胜率。

强化学习的目标变成：

```text
让策略在自我对弈中赢更多棋
```

这一步非常关键。它把训练目标从：

```text
像人类
```

改成：

```text
赢棋
```

这也回应了前面关于“人类可能下臭棋”的问题：强化学习阶段可以纠正一部分只靠模仿人类带来的偏差。

**3. 自我对弈方式**

论文采用的方式是：

```text
当前策略网络 pρ
vs
过去某个版本的策略网络
```

不是一直和自己当前版本对弈，而是从历史版本池里随机选一个对手。

这样做的目的：

```text
避免策略只针对当前自己过拟合
让训练更稳定
```

如果永远只和当前自己下，策略可能陷入某些循环或针对性习惯。历史对手池能提供更丰富、更稳定的训练环境。

**4. 奖励信号**

围棋中间过程没有即时奖励，只有终局结果。

论文设定：

```text
非终局：reward = 0
终局：赢 = +1，输 = -1
```

从某一步当前玩家的视角看：

```text
zt = +1 表示当前玩家最终赢
zt = -1 表示当前玩家最终输
```

所以每一步棋最终都用整盘棋的胜负来评价。

**5. 参数更新直觉**

论文给出的更新方向是：

```text
Δρ ∝ ∂ log pρ(at|st) / ∂ρ * zt
```

直观解释：

```text
如果这盘棋最后赢了：
  提高本局中所下那些棋的概率

如果这盘棋最后输了：
  降低本局中所下那些棋的概率
```

这就是 policy gradient 的基本思想：让导致胜利的行为更可能发生，让导致失败的行为更不可能发生。

当然，这个信号很粗糙，因为一盘棋赢了不代表每一步都是好棋，输了也不代表每一步都是坏棋。但在大量自我对弈和统计平均下，策略会朝更高胜率方向移动。

**6. Section 2 的实验结果**

论文报告了几个关键结果：

- RL policy network 对 SL policy network 胜率超过 `80%`。
- 不使用搜索，只按 RL policy network 采样落子，就能对 Pachi 赢 `85%`。
- Pachi 是当时很强的开源围棋程序，使用大量 MCTS 模拟。

这个结果很重要，因为它说明：

```text
神经网络本身已经学到了很强的棋感，
不只是依赖搜索。
```

但它还不是最终 AlphaGo。最终版本还会把策略网络、价值网络和 MCTS 结合起来。

**7. 这一节的核心意义**

Section 2 完成了一个转变：

```text
从 imitation learning
到 reinforcement learning
```

也就是：

```text
从“预测高手会怎么下”
到“学习怎样更容易赢”
```

可以把前两节连起来理解：

```text
Section 1:
用人类棋谱给网络一个强起点。

Section 2:
让网络通过自我对弈超过单纯的人类模仿。
```

**本节核心**

一句话总结：

```text
AlphaGo 用监督学习策略网络作为初始策略，再通过自我对弈和 policy gradient 直接优化胜率，得到更强的强化学习策略网络。
```

读完这一节，你需要记住三点：

1. `pρ` 从 `pσ` 初始化，不是从零开始。
2. 强化学习的目标是赢棋，而不是模仿人类。
3. 自我对弈胜负信号会提高胜局中动作的概率、降低败局中动作的概率。

### 9. 阅读 Section 3：强化学习价值网络

**问：** 继续带我读第3节

**答：**

这里读论文第三个正文小节：`Reinforcement learning of value networks`。

这一节要回答的问题是：**AlphaGo 如何判断一个局面“好不好”？**

**1. Section 3 的位置**

前两节讲的是策略网络：

```text
pσ(a|s)：模仿人类高手落子
pρ(a|s)：通过自我对弈优化胜率
```

策略网络回答的是：

```text
这个局面下一步该往哪里下？
```

第三节开始训练价值网络：

```text
vθ(s)
```

它回答的是：

```text
给定当前局面 s，当前玩家最终赢的概率/价值是多少？
```

**2. 为什么需要价值网络**

如果没有价值网络，搜索要判断一个局面好坏，常见办法是 rollout：

```text
从当前局面开始快速模拟到终局
看最后谁赢
```

但围棋 rollout 很不稳定。因为快速 rollout policy 很弱，模拟到终局后得到的结果可能噪声很大。

价值网络的目标是直接估计：

```text
这个局面最终会不会赢
```

也就是用一次神经网络前向计算，替代大量低质量或昂贵的模拟。

**3. 价值函数的定义**

论文定义：

```text
vp(s) = E[zt | st = s, 后续双方都按策略 p 下棋]
```

直观解释：

```text
如果从局面 s 开始，
双方都按照策略 p 下到终局，
当前玩家最终胜负的期望是多少？
```

理想情况下，我们想知道最优价值函数：

```text
v*(s)
```

但这不现实。所以论文训练的是：

```text
vθ(s) ≈ vpρ(s) ≈ v*(s)
```

意思是：用神经网络 `vθ` 近似 RL policy `pρ` 对弈下的局面价值，并希望它接近真正最优价值。

**4. 训练数据怎么来**

价值网络不是从人类棋谱直接训练的，而是从自我对弈生成数据：

```text
使用 RL policy network pρ 自我对弈
得到棋局结果
抽取局面 s
用最终胜负 z 作为标签
```

训练样本形式：

```text
输入：局面 s
标签：最终结果 z
```

其中：

```text
z = +1 表示当前玩家最终赢
z = -1 表示当前玩家最终输
```

**5. 训练目标**

价值网络输出一个数：

```text
vθ(s)
```

训练目标是让它接近最终结果：

```text
z
```

论文用均方误差：

```text
(z - vθ(s))²
```

直观解释：

```text
如果局面 s 后来赢了，网络应该给它更高评价；
如果局面 s 后来输了，网络应该给它更低评价。
```

**6. 一个关键问题：为什么不能直接用完整棋谱的所有局面**

论文特别强调：朴素地用完整棋局中的所有局面训练会过拟合。

原因是同一盘棋里的连续局面高度相关：

```text
第 80 手局面
第 81 手局面
第 82 手局面
```

它们只差一两颗棋子，但标签都是同一个终局胜负。

如果把这些高度相似的局面都放进去，网络可能不是学会“局面价值”，而是记住某盘棋的结果。

论文的解决办法是：

```text
生成 3000 万个不同自我对弈局面
每个局面来自不同棋局
```

这样样本之间相关性低，能减少过拟合。

**7. 结果：价值网络比 rollout 更准**

论文 Figure 2b 比较了几种局面评估方式：

- 随机 rollout
- fast rollout policy
- SL policy rollout
- RL policy rollout
- value network

结论是：

```text
价值网络的评估通常比 fast rollout 更准确
一次价值网络评估接近很多次强 rollout 的效果，但计算量低很多
```

论文中特别指出：单次 `vθ(s)` 评估接近使用 RL policy rollout 的准确度，但计算量少约 `15000` 倍。

**8. 这一节和前两节的关系**

到这里，AlphaGo 已经有两个核心能力：

```text
policy network：告诉我们哪些点值得考虑
value network：告诉我们一个局面大概谁占优
```

后面的 MCTS 就是把这两个能力结合起来：

```text
policy network 减少搜索宽度
value network 减少搜索深度
MCTS 负责把局部搜索组织起来
```

**本节核心**

一句话总结：

```text
AlphaGo 用强化学习策略网络自我对弈生成大量局面-胜负样本，训练价值网络直接预测当前局面最终胜负，从而为 MCTS 提供强局面评估。
```

读完这一节，你需要记住三点：

1. `vθ(s)` 不是预测下一手，而是预测当前局面最终胜负。
2. 价值网络用自我对弈数据训练，而不是直接模仿人类落子。
3. 它的作用是减少搜索深度，用神经网络评估替代大量 rollout。

### 10. 阅读 Section 4：用策略网络和价值网络搜索

**问：** 继续带我读第4节

**答：**

这里读论文第四个正文小节：`Searching with policy and value networks`。

这一节要回答的问题是：**AlphaGo 如何把 policy network、value network 和 MCTS 组合成最终落子？**

前三节分别准备了三个组件：

```text
pσ：监督学习策略网络，擅长给出人类式候选落子
pρ：强化学习策略网络，优化胜率
vθ：价值网络，评估局面胜负前景
```

第 4 节讲的是最终实战搜索。重点是 Figure 3。

**1. MCTS 搜索树里存什么**

AlphaGo 的搜索树中，每条边 `(s, a)` 表示：

```text
在局面 s 下选择动作 a
```

每条边主要保存三个量：

```text
P(s,a)：先验概率，policy network 认为这步有多值得考虑
N(s,a)：访问次数，这步在搜索中被探索过多少次
Q(s,a)：动作价值，这步后续局面的平均评估
```

可以直观理解为：

```text
P：第一印象
N：搜索关注度
Q：搜索后的质量评估
```

**2. Selection：选择要探索的分支**

每次模拟从根节点开始，沿着搜索树往下走。选择动作时，不是只看当前价值 `Q`，而是看：

```text
Q(s,a) + u(s,a)
```

其中 `u(s,a)` 是探索奖励，和先验概率 `P(s,a)` 成正比，和访问次数 `N(s,a)` 成反比：

```text
u(s,a) ∝ P(s,a) / (1 + N(s,a))
```

直观解释：

```text
Q 高：这步目前看起来好
P 高：策略网络一开始就觉得这步有希望
N 低：这步还没怎么探索过，值得试试
```

所以 MCTS 在两个目标之间平衡：

```text
利用：多走目前看起来好的分支
探索：别过早忽略有潜力但访问少的分支
```

**3. Expansion：扩展叶节点**

当模拟走到一个叶节点 `sL`，AlphaGo 会扩展它。

扩展时，用监督学习策略网络 `pσ` 处理这个局面：

```text
P(s,a) = pσ(a|s)
```

也就是说，新节点下面每个合法动作的先验概率来自 policy network。

这就是 policy network 在 MCTS 中的作用：

```text
告诉搜索哪些分支更值得优先看
```

它不是直接决定最终落子，而是给搜索排序和引导。

**4. Evaluation：评估叶节点**

到达叶节点后，AlphaGo 用两种方式评估这个局面：

第一种是价值网络：

```text
vθ(sL)
```

它直接预测当前局面最终胜负。

第二种是 rollout：

```text
从 sL 开始，用 fast rollout policy pπ 快速下到终局
得到最终胜负 zL
```

然后把两者混合：

```text
V(sL) = (1 - λ) vθ(sL) + λ zL
```

直观解释：

```text
value network：更聪明，但可能有评估偏差
rollout：更直接模拟到终局，但噪声大
混合使用：减少单一评估方式的风险
```

注意：这是原始 AlphaGo 的做法。后来的 AlphaGo Zero 去掉了 rollout，只用神经网络评估。

**5. Backup：把评估结果回传**

叶节点得到评估 `V(sL)` 后，把结果沿着刚才走过的路径往回传。

每条经过的边都会更新：

```text
N(s,a)：访问次数加 1
Q(s,a)：更新为经过该边所有模拟评估的平均值
```

随着模拟次数增加，`Q` 会越来越稳定，`N` 会反映搜索真正集中在哪些走法上。

**6. 最终怎么选落子**

搜索完成后，AlphaGo 不是选 `Q` 最大的动作，而是选根节点下访问次数最多的动作：

```text
argmax_a N(s,a)
```

原因是访问次数更稳健。单次或少量模拟可能让某个动作的 `Q` 偶然偏高，但大量访问代表搜索反复确认这步值得看。

所以最终落子可以理解为：

```text
MCTS 搜索后，大家反复验证后最支持的那一步
```

**7. 一个有趣细节：搜索里为什么用 SL policy 而不是 RL policy**

论文提到，在 AlphaGo 搜索中，监督学习策略网络 `pσ` 作为搜索先验，效果反而比更强的 RL policy `pρ` 好。

原因推测是：

```text
SL policy 学人类棋谱，会给一组多样的候选好点较高概率；
RL policy 更倾向于优化单一最优选择，分布可能更尖锐。
```

MCTS 需要的是“候选分支质量和多样性”，不是只要一个最像最终答案的点。因此 `pσ` 更适合给搜索提供先验。

但价值网络是从更强的 `pρ` 生成的数据训练的，这部分更强。

**8. 工程实现**

论文还强调，深度网络计算比传统搜索启发式慢很多，所以 AlphaGo 使用异步多线程搜索：

```text
CPU：执行大量 MCTS 模拟和 rollout
GPU：并行计算 policy network 和 value network
```

最终单机版使用：

```text
40 个搜索线程
48 个 CPU
8 个 GPU
```

分布式版规模更大。

**本节核心**

一句话总结：

```text
AlphaGo 的 MCTS 用 policy network 指导探索方向，用 value network 和 rollout 评估叶节点，再通过反复模拟和回传统计选择访问次数最高的落子。
```

读完这一节，你需要记住四点：

1. `P(s,a)` 来自 policy network，是搜索先验。
2. `Q(s,a)` 是搜索后得到的动作价值。
3. `N(s,a)` 是访问次数，最终落子按它选择。
4. 原始 AlphaGo 的叶节点评估混合了 value network 和 rollout。

结论：

```text
只用 value network 的 AlphaGo 已经超过所有其他围棋程序。
但混合 value network + rollout 的版本最好。
```

论文说混合评估 `λ = 0.5` 对其他变体胜率至少 95%。

这说明两种评估有互补性：

```text
value network：近似强策略 pρ 下的局面胜负
rollout：用快速策略 pπ 直接模拟到终局
混合后比单独使用更稳
```

**6. Figure 5：解释 AlphaGo 如何选一步棋**


特别要注意：

```text
policy network 给出“第一直觉”
value network/rollout 给出“局面评估”
MCTS 访问次数给出“搜索后的共识”
```

### 12. 阅读 Section 6：Discussion

**问：** 继续带我读第6节

**答：**

这里读论文第六部分：`Discussion`。

这一节要回答的问题是：**AlphaGo 的意义是什么，它和以前的 AI 系统有什么本质不同？**

这部分不是新算法，而是作者对整篇工作的总结和外推。

**1. 作者总结了三个核心贡献**

论文说，AlphaGo 是一个结合深度神经网络和树搜索的围棋程序，达到了最强人类棋手级别。

具体贡献可以拆成三点：

```text
1. 用深度神经网络实现有效的落子选择函数
2. 用深度神经网络实现有效的局面评估函数
3. 用新的搜索算法把神经网络评估和 Monte Carlo rollout 结合起来
```

对应到前文就是：

```text
policy network：落子选择
value network：局面评估
MCTS：搜索整合
```

**2. AlphaGo 和 Deep Blue 的差异**

论文特别拿 AlphaGo 和 Deep Blue 对比。

Deep Blue 战胜 Kasparov 时，依赖的是：

```text
大规模搜索
手工设计的评估函数
大量国际象棋专家知识
```

AlphaGo 的特点不同：

```text
搜索局面数量少得多
但选择搜索位置更聪明
局面评估更精确
评估函数来自训练，而不是完全手写
```

论文说，AlphaGo 在对 Fan Hui 的比赛中，评估的局面数比 Deep Blue 当年少了数千倍。它补偿这一点的方式是：

```text
policy network：更聪明地选择要看的局面
value network：更准确地评估这些局面
```

作者认为这可能更接近人类棋手的思考方式：不是穷举所有变化，而是重点看关键变化。

**3. 监督学习和强化学习的重要性**

Discussion 强调，AlphaGo 的神经网络不是纯手工设计出来的评估器，而是通过通用学习方法从棋局中训练出来的：

```text
supervised learning：从人类棋谱学习
reinforcement learning：从自我对弈学习
```

这和传统程序中大量手写特征、手写估值规则有明显区别。

但也要准确理解：原始 AlphaGo 仍然使用了一些人工输入特征和工程设计，比如气数、提子、自吃、征子等特征。它不是完全“零知识”。真正把人类棋谱和多数特征去掉的是后来的 AlphaGo Zero。

**4. 为什么围棋有代表性**

论文说，围棋代表了 AI 中很多困难问题：

```text
决策复杂
搜索空间巨大
最优解极难直接表示
很难手写出足够好的策略函数或价值函数
```

这就是为什么围棋长期被视为 AI 的重大挑战。

AlphaGo 的意义不只是会下围棋，而是证明了一种方法：

```text
深度学习负责近似直觉和评估
树搜索负责严谨推演和选择
两者结合可以处理巨大搜索空间
```

**5. 对其他领域的展望**

论文提到，MCTS 当年在围棋上的突破也推动了很多其他领域，比如：

```text
general game-playing
classical planning
partially observed planning
scheduling
constraint satisfaction
```

作者由此提出希望：把树搜索、policy network、value network 结合起来，也可能帮助解决其他看似难以处理的 AI 决策问题。

这里要注意措辞：论文不是证明 AlphaGo 方法能直接解决所有问题，而是说它提供了一个有希望的方向。

**6. 整篇论文到这里形成闭环**

整篇文章的逻辑到 Discussion 这里闭合：

```text
问题：
围棋搜索空间太大，传统方法难以达到职业水平。

方法：
用 policy network 缩小搜索宽度；
用 value network 缩短搜索深度；
用 MCTS 综合搜索、评估和模拟。

结果：
击败所有测试中的围棋程序；
5:0 战胜 Fan Hui。

意义：
深度学习 + 搜索可以解决以前认为极难的完美信息决策问题。
```

**本节核心**

一句话总结：

```text
Discussion 把 AlphaGo 的意义从“一个强围棋程序”提升为“深度学习和树搜索结合处理巨大决策空间的一种通用范式”。
```

读完这一节，你需要记住三点：

1. AlphaGo 的关键不是暴力搜索更多，而是更聪明地搜索和评估。
2. 相比 Deep Blue，AlphaGo 的评估函数更多来自数据和学习，而不是完全手写。
3. 作者认为 policy/value network + tree search 的组合有希望推广到其他复杂决策问题。

### 13. 阅读 METHODS：技术细节总览

**问：** 继续带我读第METHODS节

**答：**

`METHODS` 不是继续讲故事，而是把正文中的算法、训练、网络结构和实验设置展开成可实现的技术细节。读这一节时，不要按“新观点”读，而要按“如果我要复现，需要哪些定义和参数”来读。

**1. Problem setting：问题形式化**

作者先把围棋放到 alternating Markov games 框架里。

关键对象：

```text
S：状态空间，包含当前局面和轮到谁下
A(s)：局面 s 下的合法动作集合
f(s,a)：下动作 a 后到达的新状态
r(s)：奖励，终局才有
p(a|s)：策略，在局面 s 下选择动作 a 的概率
vp(s)：按策略 p 下棋时，局面 s 的期望胜负
v*(s)：双方完美下棋时的最优价值函数
```

这里的目的，是把前文的 policy network 和 value network 放到严格定义里：

```text
policy network 近似 p(a|s)
value network 近似 v(s)
```

**2. Prior work：和旧方法的关系**

这一段说明 AlphaGo 不是凭空出现，而是结合了两条传统路线：

```text
minimax / alpha-beta 搜索
MCTS / rollout 搜索
```

国际象棋中 alpha-beta 很强，但围棋分支太大，效果有限。

MCTS 在围棋中更成功，但传统 MCTS 的弱点是：

```text
rollout policy 质量决定搜索质量
rollout 到终局的评估经常不准
旧的 policy/value 多依赖浅层特征或手工模式
```

AlphaGo 的改进是：

```text
用深度 policy network 提供更强搜索先验
用深度 value network 直接评估局面
把完整 rollout 和截断搜索评估混合
```

**3. Search algorithm：APV-MCTS**

这一小节是 METHODS 的核心。

AlphaGo 实现的是：

```text
APV-MCTS = Asynchronous Policy and Value MCTS
```

每条边 `(s,a)` 存储：

```text
P(s,a)：policy prior
Nv(s,a)：value network 评估次数
Nr(s,a)：rollout 评估次数
Wv(s,a)：value network 累计价值
Wr(s,a)：rollout 累计价值
Q(s,a)：混合后的平均动作价值
```

正文里我们只说 `P/N/Q`，METHODS 里拆得更细，是因为 value network 和 rollout 是异步返回、分别统计的。

**4. Selection / Evaluation / Backup / Expansion**

METHODS 中四步顺序写成：

```text
Selection
Evaluation
Backup
Expansion
```

概念上仍然对应 Figure 3 的 MCTS 流程。

Selection：

```text
选择 argmax [Q(s,a) + u(s,a)]
```

探索项偏好：

```text
高先验 P
低访问次数 N
```

Evaluation：

```text
叶节点送去 value network 评估
同时用 rollout policy 模拟到终局
```

Backup：

```text
把 rollout 结果和 value network 结果分别回传
再混合成 Q
```

混合公式核心是：

```text
Q = (1 - λ) * value估计 + λ * rollout估计
```

Expansion：

```text
访问次数超过阈值 nthr 后，把后继状态加入搜索树
再异步请求 policy network 给新节点先验 P
```

**5. 异步与分布式实现**

深度网络比传统启发式慢很多，所以 AlphaGo 把工作拆开：

```text
CPU search threads：跑搜索和 rollout
GPU workers：算 policy/value network
master：维护搜索树
```

还有两个工程细节很重要：

```text
virtual loss：避免多个线程同时挤到同一分支
reuse tree：真实落子后保留对应子树，丢弃其他分支
```

最终落子仍然是：

```text
选择根节点访问次数最多的动作
```

不是选 `Q` 最大的动作，因为访问次数对异常值更稳健。

**6. Rollout policy**

rollout policy `pπ(a|s)` 是一个快策略，不是深度网络。

它是：

```text
linear softmax policy
基于局部棋形和少量手工特征
```

特征包括：

```text
候选点周围 3×3 模式
上一手附近的 response pattern
颜色、气数、局部规则特征
```

训练数据来自 Tygem 人类棋局中的 800 万个局面。

作用：

```text
不追求很强，只追求足够快
用于 MCTS 中从叶节点快速模拟到终局
```

**7. Symmetries：利用围棋对称性**

围棋棋盘有 8 种旋转/翻转对称。

AlphaGo 使用两种方式：

```text
训练时：用 8 种对称增强数据
搜索时：随机选一种对称方向做网络评估，让搜索过程平均这些结果
```

作者说，没有直接在卷积层强制旋转/翻转不变，因为这会限制大网络识别非对称模式。

**8. 三个训练细节**

Policy network: classification：

```text
KGS 6-9 段棋手
160,000 盘棋
29.4 million positions
第一百万局面作测试集
训练约 3 周
50 GPUs
```

Policy network: reinforcement learning：

```text
pρ 从 pσ 初始化
当前网络 vs 历史版本池中的网络
REINFORCE policy gradient
10,000 个 mini-batches
每批 128 盘棋
训练约 1 天
50 GPUs
```

Value network: regression：

```text
用 pρ 自我对弈生成 3000 多万个低相关局面
每盘棋只取一个训练样本，避免连续局面强相关
目标是预测最终胜负 z
训练约 1 周
50 GPUs
```

**9. 输入特征与网络结构**

policy/value network 的输入是 `19 × 19` 特征平面。

特征包括：

```text
棋子颜色
气数
可提子大小
自吃大小
落子后气数
征子相关特征
合法性
距离当前多少手
当前执黑/执白
```

policy network 输入：

```text
19 × 19 × 48
第 1 层：5×5 卷积
第 2-12 层：3×3 卷积
最后：1×1 卷积 + softmax
实战版 k = 192 filters
```

value network 输入也类似，但额外有当前颜色平面，并在后面接全连接层：

```text
卷积层
1×1 卷积
256 单元全连接层
单个 tanh 输出
```

**10. Evaluation：实验规则**

METHODS 最后说明实验细节：

```text
用 BayesElo 计算 Elo
大多数程序每步 5 秒
中国规则
贴目 7.5
Fan Hui 正式赛：1 小时主时间 + 3 次 30 秒读秒
正式赛 5 局，非正式赛 5 局
正式赛结果决定 match outcome
```

**METHODS 核心**

一句话总结：

```text
METHODS 把 AlphaGo 从概念图展开成完整工程：如何定义博弈问题，如何实现异步 MCTS，如何训练 policy/value 网络，如何构造输入特征，以及如何公平评估棋力。
```

读完 METHODS，你需要抓住三点：

1. AlphaGo 的算法核心是 APV-MCTS，不是单纯神经网络落子。
2. 原始 AlphaGo 仍然使用不少人工特征、rollout policy 和大规模工程系统。
3. 后来的 AlphaGo Zero 简化了很多东西，但这篇论文的 AlphaGo 是“监督学习 + 强化学习 + value network + rollout + MCTS + 分布式工程”的组合。

### 14. 复现 AlphaGo 所需资源和算力评估

**问：** 评估一下重现Alpha go需要的资源和算力

**答：**

结论先说：

```text
完整论文级复现：研究机构级别，普通个人基本不可行。
教学版复现：可行。
中等强度近似版：需要多 GPU、较长训练时间和大量工程。
```

**1. 论文中明确给出的训练资源**

监督学习策略网络：

```text

```


```text
50 × 7 = 350 GPU-days
```

仅神经网络训练合计约：

```text
1050 + 50 + 350 = 1450 GPU-days
```

这还不完整包含数据处理、自我对弈生成、调参失败、搜索系统开发和重复实验成本。

**2. 实战搜索资源**

**3. 数据资源**

```text
KGS 高段棋手棋谱

自我对弈数据
```

其中 KGS/Tygem 数据、清洗规则、棋力筛选、特征预处理、去重、训练/测试划分都需要工程工作。仅有论文和补充材料不够。

**4. 工程复杂度**

复现不只是训练一个 CNN。还需要：

```text
完整围棋规则引擎
合法落子与打劫处理

特征提取
rollout policy
policy/value 网络训练

virtual loss
时间管理
对局评估框架
Elo 统计
```

这些工程量可能比单纯神经网络训练更难。

**5. 分层可行性**

教学版：

```text
目标：理解算法
棋盘：5×5 或 9×9
资源：1 块普通 GPU，甚至 CPU 也能做小实验
时间：几天到几周
棋力：只用于学习，不接近原版
```

个人近似版：

```text
目标：做一个能完整跑通的 19 路简化 AlphaGo
资源：1-4 块 GPU
时间：数周到数月
难点：棋谱、围棋引擎、MCTS 性能、训练稳定性
棋力：可能达到业余弱到中等水平，取决于实现和数据
```

论文级复现：

```text
目标：接近 Fan Hui 版本 AlphaGo
资源：至少数十块 GPU + 大量 CPU
训练：千级 GPU-days
对局：单机强版本需 8 GPUs + 48 CPUs；分布式版需百级 GPUs + 千级 CPUs
周期：多人团队，数月以上
难点：不仅是算力，还有数据、工程和调参
```

**6. 粗略结论**

如果“重现”指实现算法思想：

```text
可行，建议从小棋盘 AlphaGo Zero 风格开始。
```

如果“重现”指完整复现 2016 AlphaGo 论文级棋力：

```text
需要研究机构级资源，普通个人不现实。
```

如果“重现”指复现可运行的 19 路 AlphaGo-like 系统：

```text
可行但工程量很大，最好降低目标，不追求论文棋力。
```

### 16. 一盘棋的“深度”是什么意思

**问：** 回到 Alpha go 的讨论，什么叫一盘棋的深度？

**答：**

在论文里，一盘棋的“深度” `d` 指的是从一个局面走到终局大约还需要多少步，也就是搜索树中从根节点到终局叶节点的路径长度。

更直观地说：

```text
一个局面 = 搜索树中的一个节点
下一手棋 = 从当前节点走向下一层
一盘棋下完 = 从根节点走到终局节点
路径上有多少步 = 深度 d
```

这里的“一步”通常按双方交替的每一次落子来数，而不是一整回合。

论文里用：

```text
国际象棋：b ≈ 35, d ≈ 80
围棋：b ≈ 250, d ≈ 150
```

其中：

```text
b = 每个局面平均有多少个候选走法，也叫分支因子或宽度
d = 一盘棋平均要走多少步到终局，也叫深度
```

所以搜索规模粗略是：

```text
b^d
```

深度越大，意味着从当前局面到终局需要考虑的连续决策越多；宽度越大，意味着每一步可选走法越多。围棋同时宽度大、深度大，所以穷举搜索不可行。

如果不是从开局算，而是从中盘某个局面算，那么“剩余深度”就是从该局面继续下到终局还需要的大约步数。

### 20. 价值函数是否一定是概率

**问：** 价值函数是一个值，并不一定是概率？

**答：**

是的，更准确地说：**价值函数本质上是一个期望回报，不一定天然就是概率。**

在强化学习里，一般定义为：

```text
v^p(s) = 从局面 s 开始，之后按策略 p 行动时的期望累计回报
```

它的数值含义取决于奖励怎么定义。

在 AlphaGo 这篇论文里，终局结果通常从当前玩家视角记为：

```text
赢：+1
输：-1
```

所以：

```text
v(s) = E[z | s]
```

如果没有平局，且 z 只可能是 +1 或 -1，那么：

```text
v(s) = P(赢) - P(输)
```

又因为：

```text
P(赢) + P(输) = 1
```

所以：

```text
v(s) = 2P(赢) - 1
P(赢) = (v(s) + 1) / 2
```

因此在 AlphaGo 的二值胜负设定下，价值函数可以和胜率互相转换，但它本身更准确地说是“期望胜负值”或“局面价值”，不是定义上必然的概率。

如果奖励改成：

```text
赢：1
输：0
```

那价值函数才可以直接等于胜率。

如果奖励更复杂，比如包含分差、折扣回报、过程奖励，那么价值函数就更不是概率了。

所以 slides 中更严谨的说法是：

```text
v(s)：对局面 s 的胜负价值估计
```

而不是简单说成：

```text
v(s)：胜率
```

### 21. policy network 最后一层 1x1 卷积和 softmax 的含义

**问：** 第11页中最后一层的结构是1x1卷积+softmax，也就是给每个格子一个概率？

**答：**

基本可以这样理解，但要加一个关键限定：**它给整张棋盘上的每个落点一个概率，所有落点的概率加起来为 1。**

具体地说，前面的多层卷积已经在每个棋盘位置形成了包含周围棋形和更大范围上下文的特征。最后一层 `1x1` 卷积做的是：

```text
对每个棋盘交叉点，把该位置的多通道特征压成一个分数 logit。
```

如果棋盘是 `19 x 19`，最后会得到：

```text
19 x 19 个 logits
```

然后 softmax 把这些 logits 转成概率分布：

```text
p(a | s)
```

其中：

```text
s = 当前局面
a = 某一个候选落子位置
p(a | s) = 在局面 s 下选择落子 a 的概率
```

所以它不是说“每个格子独立有一个是否落子的概率”，而是：

```text
在所有候选落子位置中，网络认为下一手最可能下在哪里。
```

直观例子：

```text
A 点：0.35
B 点：0.20
C 点：0.10
其他点合计：0.35
总和 = 1
```

`1x1` 卷积本身只在每个位置做通道融合，不再扩大空间感受野；但前面的 `5x5` 和多层 `3x3` 卷积已经把周围棋形和全局上下文编码进该位置的特征里了。

实战或搜索中还要结合合法性处理：网络输出是棋盘各点的倾向，MCTS/规则系统只会考虑合法落子。

### 22. 1x1 卷积是否独立于前面的多层卷积

**问：** 因此这个1x1卷积是独立从19x19网格做的，并不是继承自之前的多层卷积？

**答：**

不是。更准确地说：

```text
1x1 卷积在空间位置上是逐点计算的，
但它的输入特征是前面所有卷积层计算出来的。
```

也就是说，它不是直接从原始 `19 x 19` 棋盘重新判断每个点，而是接收上一层的特征图。例如上一层可以看成：

```text
19 x 19 x C
```

其中每个棋盘位置都有一个 `C` 维特征向量。最后的 `1x1` 卷积做的是：

```text
每个位置的 C 维特征向量 -> 1 个落子分数 logit
```

可以写成：

```text
z(i, j) = w · h(i, j) + b
```

其中：

```text
h(i, j) = 前面多层卷积在位置 (i, j) 得到的特征
z(i, j) = 该位置的落子分数
```

关键是：虽然最后这一步只看当前位置的特征向量 `h(i, j)`，但这个特征向量本身已经通过前面的卷积层包含了周围棋形、连接、气、攻防关系等上下文。

所以应理解为：

```text
不是：1x1 卷积独立从原始棋盘给每个格子打分
而是：前面多层卷积先提取上下文特征，最后 1x1 卷积把每个位置的特征压成一个落子分数
```

随后 softmax 再把所有位置的分数合成一个整体概率分布。

### 23. 第 12 层卷积的实际覆盖范围

**问：** 第12层实际覆盖的格子范围是多少？

```text

```

```text

```

```text

```

更严谨地说，最终每个落点的分数依赖于该落点附近、由多层卷积逐步扩大的局部区域；中心附近可以覆盖全盘，角上和边上位置不能直接覆盖对角远端。

另外，`27 x 27` 是理论感受野。神经网络中真正影响最大的区域往往集中在中心附近，这叫有效感受野。

### 26. fast rollout policy 是什么

**问：** 第12页fast rollout policy具体指什么？

**答：**

`fast rollout policy` 指的是 AlphaGo 在 MCTS 中用于快速模拟到终局的轻量策略，论文中记作：

```text
p_\pi(a | s)
```

它和前面的深度策略网络不同：

```text
p_\sigma(a | s)：监督学习训练出的深度 policy network
p_\rho(a | s)：强化学习改进后的深度 policy network
p_\pi(a | s)：快速 rollout policy
```

`fast rollout policy` 不是 13 层卷积神经网络，而是一个更简单、更快的线性 softmax 策略，使用人工设计的局部特征，例如：

```text
上一手附近的 response pattern
局部 3x3 棋形模式
气数、提子、自吃、合法性等局部规则特征
```

它的目标不是下得最强，而是：

```text
足够合理，并且极快。
```

在 MCTS 中，当搜索到一个叶节点 `s_L` 后，可以用 `fast rollout policy` 从这个局面继续快速下到终局，得到一个胜负结果：

```text
s_L -> 快速模拟若干手 -> 终局结果 z_L
```

这个 `z_L` 会作为对叶节点价值的一个估计，再回传到搜索树中。

为什么不用深度 policy network 做 rollout？因为太慢。一次 MCTS 要做大量模拟，如果每一步都调用深度 CNN，计算量会很大。论文中 fast rollout policy 的专家落子预测准确率只有约 `24.2%`，远低于深度 policy network 的 `57.0%`，但它选择一步约 `2 μs`，适合大规模模拟。

因此它的定位是：

```text
深度 policy network：慢，但质量高，用于给搜索树中的候选动作提供先验。
fast rollout policy：快，但质量低，用于从叶节点快速模拟到终局。
value network：不模拟到终局，直接估计当前局面价值。
```

原始 AlphaGo 的叶节点评估会混合 value network 和 rollout 结果；后来的 AlphaGo Zero 去掉了 fast rollout policy，只保留神经网络评估和 MCTS。

### 27. fast rollout policy 的具体结构

**问：** 有没有fast rollout policy具体什么结构的介绍？

**答：**

有。`nature16961.pdf` 的 METHODS 和 Extended Data Table 4 对它有具体说明。

`fast rollout policy` 不是卷积神经网络，而是一个线性 softmax 策略：

```text
p_\pi(a | s) = exp(π · φ(s,a)) / Σ_b exp(π · φ(s,b))
```

其中：

```text
φ(s,a) = 局面 s 下候选落子 a 的离散局部特征
π = 这些特征的权重
```

它使用的是快速、可增量计算的局部模式特征，主要分两类：

```text
response features：围绕上一手棋的应对模式
non-response features：围绕当前候选落子 a 的局部模式
```

论文 Extended Data Table 4 中 rollout policy 使用的第一组特征包括：

```text
Response              1      是否匹配某个 response pattern
Save atari            1      是否救出被打吃的棋子
Neighbour             8      是否与上一手 8 邻接
Nakade                8192   是否在被提子的地方匹配 nakade 模式
Response pattern      32207  是否匹配上一手附近的 12 点菱形模式
Non-response pattern  69338  是否匹配候选落子周围的 3x3 模式
```

其中模式基于棋子的颜色和气数：

```text
颜色：black / white / empty
气数：1 / 2 / >=3
```

所以它可以理解为：

```text
先把每个合法候选点 a 转成一串局部模式特征 φ(s,a)，
再用线性打分 π·φ(s,a)，
最后 softmax 采样一步。
```

它的训练方式类似监督学习策略网络：用 Tygem 人类棋局中的约 800 万个局面，通过随机梯度下降最大化人类实际落子的 log likelihood。

它的目标不是强，而是快：

```text
专家落子预测准确率：约 24.2%
选一步耗时：约 2 μs
空棋盘每 CPU 线程约 1000 次 rollout/s
```

另外，AlphaGo 还有一个 tree policy `p_\tau`，它和 rollout policy 类似，但特征更多。Extended Data Table 4 的第二组特征，例如 self-atari、到前两手的曼哈顿距离、候选落子周围 12 点菱形模式，是给 tree policy 增强用的，不是 fast rollout policy 的核心第一组特征。

### 33. 价值函数的直观解释

**问：** 给价值函数定义一个直观解释

**答：**

价值函数可以直观理解为：

```text
站在当前执棋方视角，这个局面最后赢棋的前景有多好。
```

在 AlphaGo 论文中，常写成：

```text
v^p(s) = E[z | s, 后续按策略 p 下棋]
```

其中：

```text
s = 当前局面
p = 之后双方采用的策略
z = 最终胜负结果
```

如果终局结果定义为：

```text
赢：+1
输：-1
```

那么：

```text
v^p(s) 接近 +1：当前局面对当前玩家非常好
v^p(s) 接近  0：胜负大致五五开
v^p(s) 接近 -1：当前局面对当前玩家很差
```

所以价值函数不是在回答“下一手下哪里”，而是在回答：

```text
从这个局面继续下，最后大概率是好结果还是坏结果？
```

它依赖策略 `p`。同一个局面，如果后面双方都乱下，价值可能是一种结果；如果双方都按强策略下，价值可能是另一种结果。

AlphaGo 的价值网络 `v_\theta(s)` 学的是用神经网络直接估计这个值，从而避免每次都必须从当前局面完整模拟到终局。

### 34. 价值函数里的策略 p 和 z_t

**问：** 也就是说，每一步都按策略p下，最后赢棋的期望？这里z_t是什么？

**答：**

基本是这个意思，但要更精确一点：

```text
v^p(s) = E[z_t | s_t = s, 后续动作按策略 p 产生]
```

表示：

```text
从当前局面 s 开始，
之后每一步都按照策略 p 来选择动作，
最后得到终局结果；
价值函数就是这个终局结果的期望。
```

这里的 `p` 可以是一个随机策略。例如 policy network 输出一组概率：

```text
p(a | s)
```

然后每一步都从这个概率分布里选动作。因为动作可能随机，所以同一个局面继续下很多次，可能得到不同终局结果；价值函数取这些结果的平均。

`z_t` 不是第 `t` 步的即时奖励，而是：

```text
从第 t 步当前玩家视角看的最终胜负结果。
```

通常定义为：

```text
z_t = +1：第 t 步要下棋的这一方最终赢了
z_t = -1：第 t 步要下棋的这一方最终输了
```

所以如果从局面 `s_t` 开始，当前玩家最后赢的概率是 `70%`，输的概率是 `30%`，那么：

```text
v^p(s_t) = 0.7 × (+1) + 0.3 × (-1) = 0.4
```

如果想换成胜率：

```text
P(赢) = (v^p(s_t) + 1) / 2
```

前提是结果只有赢和输，没有平局。

因此：

```text
v^p(s) 不是一步棋的即时分数；
它是从局面 s 出发，按策略 p 下到终局后，当前玩家最终胜负的期望。
```

### 35. 下标 t 的含义

**问：** 下标t是什么含义？

**答：**

下标 `t` 表示时间步，也就是一盘棋进行到第几步。

在围棋里可以粗略理解为：

```text
t = 1：第一手
t = 2：第二手
t = 3：第三手
...
```

论文中常用：

```text
s_t = 第 t 步时的局面
a_t = 第 t 步选择的动作，也就是落子
z_t = 从第 t 步当前玩家视角看的最终胜负结果
```

例如：

```text
s_50 = 第 50 手轮到某一方下棋时的棋盘局面
a_50 = 第 50 手实际选择的落子
z_50 = 第 50 手要下棋的这一方最后是赢还是输
```

这里特别要注意 `z_t` 的视角。因为围棋双方交替下棋，所以第 `t` 步和第 `t+1` 步的“当前玩家”不同。论文把结果写成 `z_t`，是为了表示：

```text
这个终局胜负是站在第 t 步当前玩家视角看的。
```

如果黑棋最终赢了，那么：

```text
轮到黑棋下的那些时间步，z_t = +1
轮到白棋下的那些时间步，z_t = -1
```

因此，下标 `t` 不是说每一步都有一个新的终局，而是说我们在不同时间步观察同一盘棋时，要记录：

```text
当时的局面 s_t
当时的动作 a_t
从当时玩家视角看的最终结果 z_t
```

### 36. 第 13 页的 z 和价值函数里的 z_t 是否相同

**问：** 第13页的z和这里的z不是同一个意思？

**答：**

对，它们不是同一个意思。这是一个符号复用造成的混淆。

第 13 页原来写的：

```text
z(i,j) = w · h(i,j) + b
```

这里的 `z(i,j)` 只是表示第 `(i,j)` 个棋盘位置的 softmax 前分数，也就是 logit。它用于策略网络输出：

```text
每个落点一个 logit -> 对所有 logits 做 softmax -> 得到 p(a|s)
```

而价值函数 / 强化学习里的：

```text
z_t
```

表示从第 `t` 步当前玩家视角看的最终胜负结果：

```text
z_t = +1：当前玩家最终赢
z_t = -1：当前玩家最终输
```

所以：

```text
第 13 页的 z(i,j)：策略网络的落子分数 / logit
价值函数里的 z_t：终局胜负标签 / outcome
```

为了避免混淆，已将第 13 页的符号从 `z(i,j)` 改为：

```text
\ell(i,j)
```

即：

```text
\ell(i,j) = w · h(i,j) + b
```

这样 `z_t` 可以专门保留给终局胜负结果。

### 38. v_\theta(s) 中的 \theta 是什么

**问：** 第21页，v_\theta中的\theta是什么含义？

**答：**

`v_\theta(s)` 中的 `\theta` 表示价值网络的参数，也就是神经网络中所有需要训练的权重和偏置。

可以类比前面的策略网络符号：

```text
p_\sigma(a|s)：监督学习策略网络，参数是 σ
p_\rho(a|s)：强化学习策略网络，参数是 ρ
v_\theta(s)：价值网络，参数是 θ
```

其中：

```text
s = 输入局面
v_\theta(s) = 参数为 θ 的价值网络对局面 s 的价值估计
θ = 这个价值网络内部所有卷积层、全连接层的权重和偏置
```

训练价值网络时，AlphaGo 会不断调整 `\theta`，让网络输出更接近真实终局结果 `z`：

```text
v_\theta(s) ≈ z
```

直观地说：

```text
θ 决定了价值网络怎么看棋局；
训练就是调整 θ，让它越来越会判断局面好坏。
```

### 39. \rho 是否也是参数

**问：** 这里\rho也是参数？

**答：**

是的，`\rho` 也是参数，表示强化学习策略网络的参数。

论文中这几个希腊字母都用来区分不同网络或不同训练阶段的参数：

```text
\sigma：监督学习策略网络 p_\sigma(a|s) 的参数
\rho：强化学习策略网络 p_\rho(a|s) 的参数
\theta：价值网络 v_\theta(s) 的参数
\pi：fast rollout policy p_\pi(a|s) 的参数
```

所以：

```text
p_\rho(a|s)
```

意思是：

```text
由参数 \rho 决定的策略网络，在局面 s 下选择动作 a 的概率。
```

强化学习阶段一开始通常从监督学习策略初始化：

```text
\rho = \sigma
```

然后通过自我对弈和 policy gradient 调整 `\rho`，让策略不只是模仿人类，而是更倾向于提高最终胜率。

直观地说：

```text
\sigma：学人类棋谱得到的“像人下”的参数
\rho：在 \sigma 基础上自我对弈调整后的“更想赢”的参数
\theta：用来判断局面好坏的价值网络参数
```

### 42. v_\theta 是否是对 v^{p_\rho} 的局部改进记录

**问：** 这里v_\theta相当于对v^{p_\rho}的一种局部改进记录？

**答：**

这个理解有一部分接近，但“局部改进记录”这个说法不够准确。

更准确地说：

```text
v_\theta(s) 是对 v^{p_\rho}(s) 的全局函数近似。
```

它不是一个局面表，也不是把每个局面的改进结果逐条记录下来。它是一个神经网络：

```text
输入：局面 s
输出：这个局面的价值估计 v_\theta(s)
参数：θ
```

训练数据来自 `p_\rho` 的自我对弈：

```text
局面 s  ->  该局最后胜负 z
```

训练目标是让：

```text
v_\theta(s) ≈ z
```

大量这样的样本合在一起，就让 `v_\theta` 学会近似：

```text
v^{p_\rho}(s) = 按 p_\rho 继续下时的期望胜负
```

所以它更像是：

```text
把很多自我对弈 rollout 的统计结果，压缩进一个神经网络函数里。
```

它的优势是可以泛化。即使遇到训练集中没有出现过的新局面，也可以根据棋形特征给出估值。

另外，`v_\theta` 本身不是直接“改进” `p_\rho` 的记录。真正让落子变强的是 MCTS：

```text
p_\rho / p_\sigma 给候选方向；
v_\theta 评估局面；
MCTS 综合搜索后选择更好的动作。
```

因此更严谨的说法是：

```text
v_\theta 是对 v^{p_\rho} 的神经网络近似；
它不是局部改进记录，而是一个可泛化的局面价值评估器。
```

### 43. 价值网络是否像动态规划

**问：** 有点像动态规划？

**答：**

有相似的思想，但不是经典动态规划。

相似点在于：动态规划和价值网络都试图把“从当前局面往后很长一段的结果”压缩成一个值。

动态规划里常见形式是：

```text
V(s) = 当前状态 s 的长期价值
```

AlphaGo 的价值网络也是：

```text
v_\theta(s) = 当前局面 s 的价值估计
```

所以在直觉上，它们都在做一件事：

```text
不必每次都完整推演到终局；
先学会/存下某个局面的价值；
以后遇到类似局面时直接估值。
```

这点确实很像动态规划中的“用子问题价值避免重复计算”。

但区别也很重要：

经典动态规划通常需要：

```text
明确的状态集合
明确的转移概率
能枚举动作和后继状态
用 Bellman 方程反复更新 V(s)
```

围棋中这些条件几乎不可行：

```text
状态空间太大，无法枚举所有棋盘局面；
动作空间很大；
精确最优价值 v^*(s) 不可计算；
不可能为每个局面存一个表。
```

所以 AlphaGo 不是做精确 DP，而是做近似：

```text
用自我对弈产生样本；
用神经网络 v_\theta(s) 拟合这些局面的最终胜负；
让网络对没见过的新局面也能泛化估值。
```

另外，原始 AlphaGo 的价值网络训练更接近 Monte Carlo 回归：

```text
局面 s -> 最终结果 z
训练 v_\theta(s) 接近 z
```

它不是严格按照 Bellman 方程逐步更新的表格动态规划。

更准确的定位是：

```text
AlphaGo 借用了动态规划/强化学习中的价值函数思想，
但实现上是“大规模自我对弈 + 神经网络函数近似 + MCTS 搜索”。
```

如果说“有点像动态规划”，可以这样理解：

```text
像：都用价值函数总结未来；
不像：不是枚举状态表，也不是精确 Bellman 备份。
```

### 44. 是否像机器给自己制造棋谱

**问：** 或者有点像机器给自己制造棋谱？

**答：**

这个比喻很接近，尤其适合理解价值网络的数据来源。

AlphaGo 的价值网络训练确实可以理解为：

```text
机器先用强化学习策略 p_\rho 自己下大量棋；
这些自我对弈棋局形成“机器自己制造的棋谱”；
再从这些棋谱中抽取局面 s 和最终胜负 z；
用 (s, z) 来训练价值网络 v_\theta(s)。
```

也就是：

```text
自我对弈棋谱
  -> 抽取局面
  -> 记录这盘棋最后谁赢
  -> 训练网络判断类似局面的胜负前景
```

但要注意一点：价值网络不是简单背棋谱。

它不是记录：

```text
这个局面出现过，最后赢了；
那个局面出现过，最后输了。
```

而是学习棋形和胜负之间的统计关系。训练好以后，即使遇到训练棋谱中没有出现过的新局面，也能估计：

```text
这个局面像不像会赢？
```

所以这个比喻可以更精确地说成：

```text
机器自己制造训练棋谱，
再从棋谱中学习一个可泛化的局面评估函数。
```

这也是原始 AlphaGo 从“模仿人类棋谱”走向“自我对弈改进”的关键一步。

### 46. MCTS 中 (s,a) 的含义

**问：** 第26页，(s,a)代表从局面s出发，可以选择的下一步a?

**答：**

是的，基本可以这样理解。

在第 26 页中：

```text
s = 当前棋盘局面，也就是搜索树中的一个节点
a = 在局面 s 下可以选择的一个动作，在围棋里就是一个候选落子
(s,a) = 从局面 s 选择动作 a 的这条边
```

所以 `(s,a)` 不是一个新局面，而是：

```text
局面 s 下的某一个候选分支。
```

如果从局面 `s` 下动作 `a`，会得到下一个局面：

```text
s' = f(s,a)
```

MCTS 会在每条边 `(s,a)` 上保存统计量：

```text
P(s,a)：policy network 一开始认为这个动作有多值得考虑
N(s,a)：搜索过程中这条边被访问了多少次
Q(s,a)：搜索后估计这个动作的平均价值
```

直观地说：

```text
P(s,a) = 第一印象
N(s,a) = 看过多少次
Q(s,a) = 看过之后觉得这步质量如何
```

因此：

```text
(s,a) 表示“在局面 s 下选择动作 a”这个具体选择；
MCTS 不是只评估局面，也会评估每个局面下的不同候选动作。
```

### 47. P(s,a) 是否是关于 a 的概率分布

**问：** 于是P(s, a)应该是个关于a的概率分布？

**答：**

对。更精确地说：

```text
固定局面 s 后，P(s,a) 随着 a 变化，构成关于候选动作 a 的概率分布。
```

也就是：

```text
P(s, a_1), P(s, a_2), ..., P(s, a_k)
```

表示 policy network 对局面 `s` 下各个合法候选动作的先验概率。

它们通常满足：

```text
Σ_a P(s,a) = 1
```

这里的求和是对局面 `s` 下的合法候选动作求和。

所以：

```text
P(s,a) 单独看：是动作 a 的一个概率值
P(s,\cdot) 整体看：是当前局面 s 下所有动作的概率分布
```

在 AlphaGo 的 MCTS 中，`P(s,a)` 来自 policy network：

```text
P(s,a) = p_\sigma(a|s)
```

它表示搜索刚展开节点时的“第一印象”：策略网络认为动作 `a` 有多值得优先探索。

后续搜索不会只听 `P`，还会结合：

```text
N(s,a)：访问次数
Q(s,a)：搜索后估计的动作价值
```

所以可以理解为：

```text
P(s,\cdot) 给 MCTS 一个初始的动作概率分布，
MCTS 再通过搜索把这个先验修正成更可靠的选择。
```

### 50. MCTS 中 u(s,a) 的含义

**问：** 第28页中的u(s,a)是什么？

**答：**

`u(s,a)` 是 MCTS 选择分支时的探索奖励项，也可以理解为 exploration bonus。

第 28 页的选择公式是：

```text
a_t = argmax_a [ Q(s_t,a) + u(s_t,a) ]
```

其中：

```text
Q(s,a)：当前搜索认为动作 a 的价值有多高
u(s,a)：为了探索而额外加上的奖励
```

如果只看 `Q(s,a)`，搜索可能很快集中到目前看起来最好的几步，忽略一些还没充分检查、但可能更好的候选动作。`u(s,a)` 的作用就是：

```text
给“值得试但还没看够”的动作一个额外加分。
```

AlphaGo 中探索项近似满足：

```text
u(s,a) ∝ P(s,a) / (1 + N(s,a))
```

所以：

```text
P(s,a) 大：policy network 觉得这步有希望，u 较大
N(s,a) 小：这步还没怎么搜索过，u 较大
N(s,a) 变大：这步已经看过很多次，u 逐渐变小
```

直观地说：

```text
Q(s,a)：这步目前看起来好不好
u(s,a)：这步是否还值得再探索一下
Q + u：在利用已知好招和探索潜在好招之间做平衡
```

因此 `u(s,a)` 不是神经网络直接输出的价值，而是 MCTS 为了控制搜索行为加上的探索项。

### 51. MCTS 中 Evaluation 为什么评估叶节点

**问：** 第28页中Evaluation为何是评估叶节点？而不是下一步的节点？

**答：**

这里的“叶节点”不是指整盘棋的终局节点，而是指当前搜索树已经展开到的边界节点。

MCTS 一次模拟不是只看当前局面的下一步，而是会沿着搜索树往下走多步：

```text
当前局面 s
  -> 选择动作 a_1
  -> 到达下一个局面 s_1
  -> 再选择动作 a_2
  -> 到达 s_2
  -> ...
  -> 到达当前搜索树中还没有充分展开的边界节点 s_L
```

这个 `s_L` 就叫 leaf node，叶节点。

为什么评估叶节点？因为前面的路径已经由 Selection 过程决定了。MCTS 要回答的是：

```text
如果从当前局面沿着这条候选路线继续走下去，最后前景怎么样？
```

所以它需要评估路线末端的局面 `s_L`，再把这个评估结果回传给路径上的每条边。

如果只评估下一步节点 `s_1`，搜索深度就只有 1，无法体现多步搜索。MCTS 的价值正在于：

```text
沿着有希望的分支往下看很多步，
在叶节点评估局面，
再把结果回传更新前面每一步的 Q 和 N。
```

原始 AlphaGo 对叶节点 `s_L` 的评估有两种：

```text
value network：直接估计 v_\theta(s_L)
fast rollout policy：从 s_L 快速模拟到终局，得到 z_L
```

然后混合成叶节点评估值：

```text
V(s_L) = (1 - λ) v_\theta(s_L) + λ z_L
```

因此 Evaluation 评估叶节点，是因为一次 MCTS 模拟的选择阶段已经走到搜索树边界；评估那里，才能把这条多步路线的结果反馈给整条路径。

### 52. Evaluation 是否会模拟到终局

**问：** 也就是说会模拟到终局？

**答：**

在原始 AlphaGo 中，答案是：**部分会，部分不会。**

到达叶节点 `s_L` 后，AlphaGo 同时做两类评估：

1. value network 评估：

```text
直接计算 v_\theta(s_L)
```

这一步不会模拟到终局。神经网络直接根据当前叶节点局面估计胜负前景。

2. rollout 评估：

```text
从 s_L 开始，用 fast rollout policy 快速下到终局，得到 z_L
```

这一步会模拟到终局。

然后 AlphaGo 把二者混合：

```text
V(s_L) = (1 - λ) v_\theta(s_L) + λ z_L
```

所以更准确地说：

```text
MCTS 的 selection 阶段先走到叶节点 s_L；
Evaluation 阶段用 value network 直接估计 s_L；
同时也用 fast rollout policy 从 s_L 模拟到终局；
最后混合两种结果并回传。
```

后来的 AlphaGo Zero 去掉了 rollout，不再从叶节点快速模拟到终局，而是只使用神经网络价值评估加 MCTS。

### 53. 如何判断到达搜索树边界即叶节点

**问：** 如何判断已经到边界，即叶节点？

**答：**

这里的边界是“当前搜索树的边界”，不是围棋规则意义上的终局。

MCTS 维护的是一棵逐步增长的搜索树。一次模拟从根局面开始，沿着已经在树里的边往下走：

```text
s_0 -> s_1 -> s_2 -> ...
```

只要当前局面已经在搜索树中，并且有可选择的已展开动作，Selection 就可以继续往下走。

当遇到下面情况之一，就可以认为到达了叶节点：

```text
1. 当前局面还没有被加入搜索树；
2. 当前局面已经在树里，但还没有展开它的后继动作；
3. 某条边的访问次数达到扩展条件后，生成了一个新节点，这个新节点就是当前模拟的叶节点；
4. 当前局面本身已经是终局。
```

在 AlphaGo 的 METHODS 中，Expansion 条件大致是：

```text
当某条边 (s,a) 的访问次数超过阈值 n_thr 时，
把后继局面 s' = f(s,a) 加入搜索树。
```

论文里 `n_thr = 40`。

所以可以直观理解为：

```text
Selection：沿着树中已有、值得探索的边往下走；
Expansion：当某条边看得足够多，就把它的后继局面加入树；
Evaluation：对新加入或当前边界处的局面做评估；
Backup：把评估结果回传。
```

因此，叶节点不是固定的。随着 MCTS 模拟次数增加，原来的叶节点会被展开，搜索树变深，新的边界会出现在更深的地方。

一句话：

```text
叶节点 = 当前这棵搜索树中，Selection 走到的最前沿局面；
它可能不是终局，只是还没有继续展开。
```

### 54. 叶节点和当前搜索树扩张范围的关系

**问：** 所以和当前树的扩张范围有关

**答：**

对，完全正确。

MCTS 中的“叶节点”是相对于当前已经扩张出来的搜索树而言的。

同一个真实棋局状态，在不同搜索时刻可能有不同身份：

```text
刚开始：它可能还不在树里
被第一次加入树时：它是叶节点
继续搜索后：它可能被展开，变成内部节点
再往下的新局面：成为新的叶节点
```

所以叶节点不是棋局本身固定的属性，而是：

```text
当前搜索树扩张到哪里，哪里就是边界；
Selection 走到这个边界，就到达叶节点。
```

这也是为什么 MCTS 是“逐步长树”的：

```text
先浅浅看很多候选；
发现某些分支有希望，就沿这些分支继续扩张；
树的边界不断向更深处推进。
```

一句话总结：

```text
叶节点 = 当前搜索树扩张范围的前沿。
```

### 55. Selection 是否一定触发新节点

**问：** Selection动作一定会触发新节点么？也可能停留在老的路径，从而增加N(s,a)值？

**答：**

对，Selection 不一定触发新节点。

Selection 的作用只是：

```text
在当前已经存在的搜索树中，按照 Q(s,a)+u(s,a) 选择一条边往下走。
```

这次模拟经过的边会增加访问统计，例如：

```text
N(s,a) 增加
Q(s,a) 在 backup 后更新
```

但是否扩展新节点，要看 Expansion 条件是否满足。

在 AlphaGo METHODS 里，扩展大致发生在：

```text
某条边 (s,a) 的访问次数 N_r(s,a) 超过阈值 n_thr
```

论文参数中：

```text
n_thr = 40
```

也就是说，一条边可能先被访问很多次，只是在已有树上累计统计量；直到访问次数足够多，系统才把后继局面：

```text
s' = f(s,a)
```

加入搜索树。

所以一次模拟可能出现几种情况：

```text
1. 只沿已有路径走，更新 N 和 Q，没有扩展新节点；
2. 走到某条达到扩展条件的边，新增后继节点；
3. 走到终局，直接得到结果并回传。
```

因此你的理解是对的：

```text
Selection 可以反复走老路径，
这些访问会增加 N(s,a)，
但新节点只有在满足扩展条件时才会产生。
```

### 59. 在 Selection 和 Evaluation 之间补充 Expansion 页

### 60. Expansion 中“访问足够多”的含义

**问：** 这里访问的足够多，是指参与搜索就算一次访问？

**答：**

基本是的，但要精确限定：

```text
一次 MCTS 模拟中，如果 Selection 路径经过某条边 (s,a)，
这条边在 Backup 时通常会把访问次数 N(s,a) 加 1。
```

所以“访问足够多”不是指：

```text
这个局面被网络看了一眼；
也不是局面 s 下所有候选动作都同时访问一次。
```

而是指：

```text
某个具体分支 (s,a) 在多次搜索模拟中被实际选中、经过了多少次。
```

例如在根局面 `s` 下有三个候选动作：

```text
a_1, a_2, a_3
```

如果一次模拟选择了 `a_2`，那么这次只会增加和实际路径相关的统计量，例如：

```text
N(s,a_2) += 1
```

不会让 `N(s,a_1)` 和 `N(s,a_3)` 同时增加。

直观理解：

```text
N(s,a) = 这条路已经被搜索实际走过多少次。
```

当某条路被走过足够多次，AlphaGo 才认为它值得把后继局面 `s'=f(s,a)` 加入搜索树继续细看。

### 61. 动作边已在 MCTS 中为何还需要 Expansion

**问：** 如果一步已经在MCT上，那么它的后续局面应该已经有了，为何还需要扩展？

**答：**

这里要区分两件事：

```text
边 (s,a) 已经在树里有统计量；
后继局面 s'=f(s,a) 已经作为一个树节点展开。
```

这两件事不是同一层含义。

当局面 `s` 被加入搜索树时，MCTS 可以先为 `s` 下的候选动作建立边统计量：

```text
P(s,a), N(s,a), Q(s,a)
```

这表示“从 `s` 选择 `a` 这条分支”已经有了先验和访问统计。但此时后继局面：

```text
s' = f(s,a)
```

可能只是规则上可以计算出来，并没有被登记为搜索树中的节点，也没有为 `s'` 的下一步动作建立：

```text
P(s',a'), N(s',a'), Q(s',a')
```

所以 Expansion 的作用不是“规则上第一次知道 `s'` 存在”，而是：

```text
把 s' 从一个隐含的后继局面，正式加入搜索树；
并初始化 s' 往下所有候选动作的先验和统计量。
```

如果 `s'` 已经在搜索树中，就不需要对这条边重复扩展；Selection 会继续从 `s'` 往更深处走。需要扩展的是当前树的前沿，也就是还没有作为节点展开的后继局面。

直观比喻：

```text
边 (s,a) 存在：地图上知道有一条路。
s' 被扩展：真的走到路口，并把这个路口后面的岔路也画出来。
```

### 62. P(s,a) 与 MCTS 实际展开分支的关系

**问：** 也就是说P(s,a)不是MCT上的全部分支，而是全步可能步的全部分支，而MCT只激活感兴趣的分支？

**答：**

这个理解基本正确，但可以更精确地分成三层：

```text
1. 合法动作层：局面 s 下所有合法落子 a。
2. 先验概率层：当 s 被展开时，policy network 给每个合法动作分配 P(s,a)。
3. 搜索树展开层：MCTS 只会反复访问、进一步扩展其中一部分分支。
```

所以固定一个已经展开的局面 `s` 后：

```text
P(s,\cdot)
```

通常是关于 `s` 下所有合法动作的概率分布。它表示策略网络对所有候选落子的第一印象。

但 MCTS 不会把所有合法动作的后续局面都一路展开下去。它会根据：

```text
Q(s,a) + u(s,a)
```

反复选择更值得看的分支。只有实际被选中过的边，访问次数 `N(s,a)` 才会增加；只有被访问到足够程度的边，后继局面 `s'=f(s,a)` 才会被正式扩展成树节点。

因此可以这样理解：

```text
P(s,a)：给所有合法候选步一个先验排序。
MCTS：从这些候选步里优先激活、访问、扩展最值得搜索的少数分支。
```

需要注意一个细节：

```text
如果局面 s 还没有被扩展，P(s,a) 通常还没有被计算并登记到树里。
```

也就是说，不是整盘棋所有可能局面的一切 `P(s,a)` 都预先存在；而是搜索树扩展到某个局面 `s` 时，才为这个局面的合法动作生成先验分布。

### 65. MCTS 已激活路径是否可以不连续

**问：** MCT激活的路线可以是不连续的么？比如s1=(s,a), s1激活了,但s未激活

**答：**

通常不可以。标准 MCTS 中，搜索树是从当前根局面开始逐步长出来的，所以任意一个已经加入树的节点，其父节点以及从根到它的整条路径都必须已经在树中。

更准确的记号是：

```text
s = 父局面
a = 从 s 出发选择的动作
s_1 = f(s,a) = 下完 a 后的后继局面
(s,a) = 从 s 到 s_1 的边
```

所以如果后继局面 `s_1` 已经被扩展成 MCTS 节点，那么：

```text
s 必须已经在树中；
(s,a) 这条边也必须已经被搜索走过。
```

不会出现：

```text
s_1 已经是树节点，但它的父局面 s 不在树中。
```

不过 MCTS 的树可以是“稀疏”的。稀疏指的是：

```text
在同一个父局面 s 下，不是所有合法动作都会被访问或扩展；
只有一部分有希望的分支被激活。
```

因此：

```text
父子路径必须连续；
兄弟分支可以非常稀疏。
```

还要区分“边已有统计”和“后继节点已展开”：

```text
s 已展开时，可能已经有 P(s,a) 这样的候选边先验；
但 s_1=f(s,a) 还不一定被扩展成节点。
```

反过来，如果 `s_1` 已经被扩展成节点，那么它前面的 `s` 和 `(s,a)` 一定已经存在。

### 68. 橙色路径末端叶子是否必然扩展

**问：** 所以下一步，橙色路线的叶子必会被扩展？

**答：**

不一定。更准确地说：

```text
橙色路线末端 = 本次模拟选中的边界/叶子；
它一定会被本次模拟处理；
但不一定每次都会被扩展出下一层。
```

在很多简化版 MCTS 教材里，流程常写成：

```text
Selection -> Expansion -> Evaluation -> Backup
```

因此容易理解成“选到叶子后必然扩展”。但在 AlphaGo 论文的实现里，Expansion 是有条件的。论文 METHODS 中的条件是：

```text
当访问次数超过阈值：N_r(s,a) > n_thr
才把后继局面 s'=f(s,a) 插入搜索树。
```

所以本次模拟到达橙色路径末端后，可能发生：

```text
1. 对该叶子做 value network / rollout evaluation，然后 backup；
2. 如果相关边的访问次数达到阈值，再把后继局面扩展进树；
3. 如果它已经是终局，则不再扩展。
```

因此一句话：

```text
橙色路径末端是本次模拟选中的叶子；
它是 expansion 的候选对象，但不是必然马上扩展。
```

### 70. MCTS 结果是否会改进强化学习参数

**问：** 第33页指出搜索中用的是监督学习，那么MCTS结果是否会改进强化学习的参数？

**答：**

在原始 AlphaGo 论文里，答案基本是：

```text
不会。
```

第 33 页说的“搜索中用 SL policy”指的是：MCTS 在搜索时使用监督学习策略网络 `p_\sigma(a|s)` 作为先验，帮助判断哪些候选落子更值得先探索。

这时 `p_\sigma` 的作用是：

```text
给 MCTS 提供候选分支先验 P(s,a)
```

而不是：

```text
让 MCTS 的结果反向更新 p_\sigma 或 p_\rho 的参数
```

原始 AlphaGo 的流程更像一个分阶段管线：

```text
1. 用人类棋谱训练 SL policy p_\sigma
2. 从 p_\sigma 初始化，强化学习训练 RL policy p_\rho
3. 用 p_\rho 自我对弈生成数据，训练 value network v_\theta
4. 实战时固定这些网络参数，用 MCTS 做搜索决策
```

所以在第 4 步中，MCTS 会改进“当前局面的决策”，但不会改进“网络参数”。

可以这样理解：

```text
MCTS 输出的是这一手该怎么下；
不是输出一个新的梯度来训练 p_\rho。
```

搜索统计量，例如：

```text
N(s,a), Q(s,a)
```

只保存在当前搜索树里，用来选择当前根节点的最终落子。下一步棋到了新局面，会重新建立或推进搜索树；神经网络权重本身不因为这次搜索自动改变。

需要和后来的 AlphaGo Zero / AlphaZero 区分开：

```text
原始 AlphaGo：MCTS 主要用于实战决策，不反向训练策略网络。
AlphaGo Zero / AlphaZero：自我对弈时用 MCTS，MCTS 的访问次数分布会作为训练目标，反过来训练新的网络。
```

所以，如果问第 33 页对应的原始 AlphaGo：

```text
搜索中用了 SL policy；
MCTS 结果不会改进 RL policy 的参数。
```

如果问后来的 AlphaZero 式训练：

```text
MCTS 结果会成为改进策略网络的监督信号。
```

### 72. 第 7 页体现价值网络对强化学习的增强作用

**问：** 第7页应该体现价值网络对强化学习的增强作用。

**答：**

这个修正是对的。原始 AlphaGo 的 METHODS 里有一个细节：

```text
第一轮 RL policy 训练时，baseline 设为 0；
第二轮训练时，使用 value network v_\theta(s) 作为 baseline；
这带来了 small performance boost。
```

这里的 baseline 不是 MCTS 搜索结果，而是 policy gradient 里的方差降低项。强化学习更新大致是：

```text
\Delta \rho \propto \nabla_\rho \log p_\rho(a_t|s_t) (z_t - v(s_t))
```

如果没有好的 baseline，就用最终胜负 `z_t` 直接推动参数，梯度方差会比较大。使用 `v_\theta(s_t)` 后，更新更像是：

```text
实际结果 z_t - 当前局面本来预期的胜率 v_\theta(s_t)
```

这样可以更稳定地判断某一步比预期好还是差，从而小幅增强 `p_\rho` 的训练。

因此第 7 页应该同时表达三条关系：

```text
1. p_\rho -> 自我对弈 -> v_\theta
2. v_\theta -> p_\rho：作为第二轮 RL baseline，小幅增强强化学习
3. p_\sigma 和 v_\theta -> MCTS：搜索时分别提供先验和局面评估
```

### 73. 对 AlphaGo 训练管线的整体理解

**问：** 现在是否可以这样理解：监督学习网络，提供了强化学习网络的参数初值，以及MCTS中的网络节点初始概率。强化学习网络提供了价值网络。价值网络，提供了MCTS中的搜索依据。而实际下棋的是MCTS策略。

**答：**

基本可以这样理解，但建议把表述改得更精确一点。

更准确的版本是：

```text
监督学习策略网络 p_\sigma：
1. 提供强化学习策略网络 p_\rho 的参数初值；
2. 在 MCTS 中为新展开局面的每个合法动作提供先验概率 P(s,a)。

强化学习策略网络 p_\rho：
1. 从 p_\sigma 初始化；
2. 通过自我对弈优化“赢棋”目标；
3. 生成自我对弈局面-胜负数据，用来训练价值网络 v_\theta。

价值网络 v_\theta：
1. 近似 p_\rho 自我对弈下的局面价值 v^{p_\rho}(s)；
2. 在 MCTS 中评估叶节点局面，提供局面好坏判断；
3. 在第二轮 RL 中还可作为 baseline，小幅增强 p_\rho 的训练。

MCTS：
1. 用 p_\sigma 给出的 P(s,a) 指导探索宽度；
2. 用 v_\theta 和 fast rollout policy 评估叶节点；
3. 通过反复模拟、回传 N(s,a)、Q(s,a)；
4. 最终在根节点选择访问次数最多的动作。
```

需要修正的两个小点：

第一，`p_\sigma` 在 MCTS 中提供的不是“网络节点初始概率”，而是：

```text
动作先验概率 P(s,a)
```

也就是在局面 `s` 下，每个合法落子 `a` 一开始看起来有多值得探索。

第二，价值网络不是 MCTS 的唯一搜索依据。原始 AlphaGo 的 MCTS 同时依赖：

```text
P(s,a)：来自 SL policy p_\sigma 的动作先验
N(s,a)：这条边被访问了多少次
Q(s,a)：这条边历史模拟的平均价值
u(s,a)：鼓励探索的 bonus
v_\theta(s_L)：价值网络对叶节点的评估
z_L：fast rollout policy 模拟到终局的结果
```

所以最后一句可以这样说：

```text
实际下棋的不是单独的 SL policy、RL policy 或 value network，
而是由 MCTS 综合这些信号后，在根节点选择访问次数最多的动作。
```

压缩成一条主线就是：

```text
p_\sigma 给起点和搜索先验；
p_\rho 把目标从“像人”改成“赢棋”；
p_\rho 的自我对弈训练出 v_\theta；
v_\theta 帮 MCTS 判断局面；
最终落子由 MCTS 的搜索统计决定。
```

### 75. 对 METHODS 部分做进一步详细解读

**问：** 对论文的Method部分，可否做进一步详细的解读？

**答：**

可以。METHODS 部分建议不要当成“又一段正文”读，而要当成 AlphaGo 的工程说明书读。正文回答的是：

```text
AlphaGo 为什么有效？
```

METHODS 回答的是：

```text
如果要把这个系统做出来，具体对象、公式、训练数据、搜索流程和工程实现是什么？
```

可以按 8 条主线读。

**1. Problem setting：先把围棋写成数学对象**

论文先定义：

```text
s：状态，包含棋盘和轮到谁下
A(s)：状态 s 下的合法动作集合
f(s,a)：在 s 下走 a 后到达的新状态
p(a|s)：策略，在 s 下选择 a 的概率
z：终局胜负结果
v^p(s)：按策略 p 下棋时，状态 s 的期望胜负
v*(s)：完美下棋下的最优价值
```

这里最重要的是 `v*(s)` 的递归定义：

```text
终局：v*(s) = z
非终局：v*(s) = max_a -v*(f(s,a))
```

为什么有一个负号？因为围棋是零和博弈。你走完一步后，轮到对手下；从对手视角好的局面，对你就是坏局面。所以每往下一层，视角会翻转。

这一节的作用是把后面的网络放进严格位置：

```text
policy network 近似 p(a|s)
value network 近似 v(s)
MCTS 近似 v*(s) 或更好的动作选择
```

**2. Prior work：说明 AlphaGo 不是单独发明一个东西**

论文把旧路线分成两类。

第一类是 minimax / alpha-beta：

```text
尽量向下搜索；
搜不到终局时，用近似价值函数截断。
```

这在国际象棋很强，但围棋分支因子太大，传统 alpha-beta 不够有效。

第二类是 MCTS：

```text
用大量模拟估计动作价值；
搜索越多，统计越可靠。
```

MCTS 有两个近似：

```text
用有限次数模拟近似某个搜索策略下的价值；
用当前搜索策略近似最优策略。
```

AlphaGo 的关键不是抛弃 MCTS，而是给 MCTS 两个更强的组件：

```text
更强的 policy：让搜索先看更有希望的动作；
更强的 value：不必总是 rollout 到终局才能评估局面。
```

**3. Search algorithm：APV-MCTS 是 METHODS 的核心**

APV-MCTS 全称可以理解为：

```text
Asynchronous Policy and Value MCTS
```

即异步地把 policy network 和 value network 接进 MCTS。

正文里我们常说一条边 `(s,a)` 存：

```text
P(s,a), N(s,a), Q(s,a)
```

METHODS 里更细，边上存：

```text
P(s,a)：动作先验概率
Nv(s,a)：value network 评估经过这条边的次数
Nr(s,a)：rollout 经过这条边的次数
Wv(s,a)：value network 评估累计值
Wr(s,a)：rollout 结果累计值
Q(s,a)：混合后的平均动作价值
```

为什么要把 `v` 和 `r` 分开？因为原始 AlphaGo 同时有两种叶节点评估：

```text
value network：慢但直接评估局面；
rollout：快策略模拟到终局，得到真实胜负样本。
```

二者的返回时间和统计来源不同，所以 METHODS 里分开维护。

**4. APV-MCTS 的四个阶段**

METHODS 写成四步：

```text
Selection -> Evaluation -> Backup -> Expansion
```

Selection：

```text
a = argmax_a (Q(s,a) + u(s,a))
```

这里 `Q` 是目前看起来这步多好，`u` 是探索奖励。`u` 大致偏向：

```text
先验概率 P(s,a) 高；
访问次数 Nr(s,a) 低。
```

所以它一开始相信 policy network 的第一印象；访问多了以后，逐渐更相信真实搜索统计。

Evaluation：

```text
到达叶节点 s_L 后：
1. 把 s_L 送入 value network 队列；
2. 同时用 fast rollout policy 从 s_L 模拟到终局。
```

这说明原始 AlphaGo 不是纯 value network，也不是纯 rollout，而是混合两者。

Backup：

rollout 完成后，把终局结果沿路径回传。value network 计算完成后，也沿同一路径回传。最后组合成：

```text
Q = (1 - lambda) * value平均值 + lambda * rollout平均值
```

这里的 `lambda` 控制更信 value network 还是 rollout。

Expansion：

不是每条新边马上都展开。论文中使用阈值：

```text
Nr(s,a) > n_thr
```

当某条边访问足够多，才把后继状态 `s' = f(s,a)` 加进搜索树。新节点先用较快的 tree policy 填 placeholder prior，随后异步等 SL policy network 算出更准的：

```text
P(s',a) = p_sigma(a|s')
```

这解释了为什么 MCTS 树是逐步长出来的，而不是一次性展开所有合法分支。

**5. 异步和分布式：为什么实现这么复杂**

深度网络很强，但比传统手工启发式慢很多。如果每次 selection 都等待 GPU 返回，搜索线程会被卡住。

所以 AlphaGo 把工作拆成：

```text
master：维护搜索树，执行树内 selection；
CPU workers：执行 rollout；
GPU workers：执行 policy/value network 前向计算；
queues：把叶节点和新节点送去异步评估。
```

几个工程点很关键：

```text
virtual loss：临时给正在探索的边记一个损失，避免多个线程都挤到同一路径；
lock-free update：尽量减少多线程锁开销；
reuse tree：真实落子后，把对应子树保留下来当新根；
opponent pondering：对手思考时继续搜索；
resign threshold：胜率估计低于约 10% 时认输。
```

这部分告诉我们：原始 AlphaGo 不只是算法公式，而是一个大规模并行搜索系统。

**6. Rollout policy：为什么还需要快策略**

`p_pi(a|s)` 不是深度网络，而是线性 softmax 策略，依赖局部棋形和少量手工特征。

它的定位是：

```text
不求特别强；
只求非常快；
用于从叶节点快速模拟到终局。
```

它使用的特征包括：

```text
候选点附近 3x3 局部模式；
上一手附近的 response pattern；
颜色、气数、局部规则相关特征。
```

还有一个类似 last good reply 的技巧：搜索树中某些看起来好的应手，会被缓存下来，在 rollout 中遇到相似局部模式时优先使用。

这说明原始 AlphaGo 仍然有明显的传统围棋程序影子，并不是完全端到端。

**7. Symmetries：怎样利用围棋棋盘对称性**

围棋棋盘有 8 种旋转和翻转对称。

论文说没有把对称性硬编码进卷积滤波器，因为大网络中强制对称可能限制表达能力。它改用运行时对称增强：

```text
explicit ensemble：8 个对称变换都算一遍，再平均；
implicit ensemble：每次评估随机选一种对称变换，让 MCTS 多次模拟自然平均。
```

AlphaGo 的 APV-MCTS 用的是 implicit symmetry ensemble，因为它更省计算。

**8. 三个网络训练过程**

SL policy classification：

```text
数据：KGS 6-9 段人类棋谱
目标：预测人类下一手
损失：最大化 log p_sigma(a|s)
规模：约 2940 万局面，8 倍对称增强
作用：给 p_rho 初值，也给 MCTS 搜索先验
```

RL policy reinforcement learning：

```text
初始化：rho = sigma
对手：历史版本池中的 p_{rho-}
目标：最大化最终胜负
算法：REINFORCE policy gradient
baseline：第一轮为 0，第二轮可用 v_theta(s)
作用：把策略从“像人”推向“赢棋”
```

为什么要用历史版本池？如果永远只和当前自己下，训练目标会剧烈变化，容易不稳定。随机从旧版本池抽对手，相当于让训练环境更稳定。

Value network regression：

```text
目标：学习 v_theta(s) ≈ v^{p_rho}(s)
数据：p_rho 自我对弈产生的局面-胜负样本
损失：预测值和最终胜负 z 的均方误差
作用：给 MCTS 提供叶节点局面评估
```

这里有一个重要细节：每盘自我对弈只取一个训练样本。原因是同一盘棋里的连续局面高度相关，如果全取，会让训练集看似很大但有效多样性不足。

论文生成价值网络数据时还故意加入噪声：

```text
前 U-1 手按 SL policy 采样；
第 U 手随机走一个合法点；
后面用 RL policy 下到终局；
只取第 U+1 个局面和最终胜负。
```

这样做是为了制造更多样、低相关的局面，同时目标仍然对应“从这个局面开始按 p_rho 下到终局的期望胜负”。

**9. 输入特征和网络结构**

policy/value network 的输入不是单纯黑白棋盘图片，而是很多 `19 x 19` 特征平面。

特征包括：

```text
己方/对方棋子
气数
可提子规模
自吃规模
合法落子
距离当前多少手
征子相关特征
当前执棋颜色，value network 额外使用
```

所有特征都从“当前行棋方”的视角表示，比如不是绝对黑白，而是：

```text
player / opponent
```

这样网络不需要分别学习黑棋视角和白棋视角。

policy network 大致是：

```text
输入：19 x 19 x 48
第 1 层：5x5 卷积
第 2-12 层：3x3 卷积
输出：1x1 卷积 + softmax，得到各位置落子概率
```

value network 大致是：

```text
前面类似 policy network；
后面增加卷积层、1x1 卷积、全连接层；
最终输出一个 tanh 标量，表示胜负倾向。
```

**10. METHODS 的关键结论**

读完 METHODS 后，应该形成这个认识：

```text
原始 AlphaGo = 深度网络 + 传统搜索 + rollout + 手工特征 + 大规模异步工程。
```

它不是后来 AlphaGo Zero 那种更简洁的版本。原始 AlphaGo 的复杂性主要来自：

```text
SL policy 提供强起点和搜索先验；
RL policy 改变训练目标；
value network 缩短搜索深度；
rollout policy 保留快速终局采样；
APV-MCTS 把所有信号整合成最终落子；
分布式系统保证在时限内跑足够多模拟。
```

如果进一步精读，最值得拆开的不是所有段落平均读，而是优先读三块：

```text
1. APV-MCTS 的 P、N、W、Q、u 公式；
2. value network 数据生成为什么要用 SL 前缀 + 随机一步 + RL 后缀；
3. 原始 AlphaGo 和 AlphaGo Zero 在 METHODS 层面的差异。
```

### 77. 第 42 页 v^* 递归里的负号和 value network 近似对象

**问：** 第42页，价值函数v^*的递归为何要max_a减去？怎么理解？这里价值网络近似v(s)是否应该改成v^*(s)?

**答：**

`v^*(s)` 递归里写：

```text
v^*(s) = max_a -v^*(f(s,a))
```

关键在于论文里的价值函数是从“当前行棋方”的视角定义的。

也就是说：

```text
v^*(s) = 当前轮到下棋这一方，在最优下法下最终能得到的价值
```

如果我在状态 `s` 走一步 `a`，到达后继状态：

```text
s' = f(s,a)
```

此时轮到对手下。于是：

```text
v^*(s')
```

表示的是“对手作为当前行棋方”的价值，而不是我的价值。围棋是零和博弈，对手好就是我坏，所以从我的视角看后继局面的价值是：

```text
-v^*(s')
```

因此我在当前状态要选择让自己最好的动作：

```text
max_a -v^*(f(s,a))
```

一个直观例子：

```text
如果某步走完后，对手视角 v^*(s') = +1，
表示对手必胜，
那么我当前这步的价值就是 -1。

如果某步走完后，对手视角 v^*(s') = -1，
表示对手必败，
那么我当前这步的价值就是 +1。
```

### 78. v(s) 的定义是什么

**问：** 如果这样，v(s)的定义是什么？

**答：**

严格说，单独写 `v(s)` 时，它通常不是论文中某个唯一、精确定义的对象，而是“某个局面价值函数”的泛称或占位符。

在这篇论文里，更严谨的写法应该区分三种：

```text
v^p(s)：策略 p 下的价值函数
v^*(s)：最优价值函数
v_\theta(s)：参数为 θ 的神经网络价值函数
```

其中：

```text
v^p(s) = E[z | s, 后续动作按策略 p 产生]
```

意思是：从局面 `s` 开始，如果双方后面都按策略 `p` 下，当前行棋方最终胜负结果的期望。

```text
v^*(s)
```

意思是：从局面 `s` 开始，如果双方都完美下棋，当前行棋方能得到的最优价值。

```text
v_\theta(s)
```

意思是：价值网络对局面 `s` 的输出。它是一个函数近似器，有训练参数 `\theta`。

所以如果在引言或 slides 里看到：

```text
v(s) ≈ v^*(s)
```

它的意思通常是：

```text
我们想要一个可计算的局面评估函数 v(s)，用它近似不可计算的最优价值 v^*(s)。
```

这里的 `v(s)` 是泛称，可以是：

```text
手工评估函数；
rollout 估计；
神经网络 value function；
其他任何近似局面评估器。
```

但放到原始 AlphaGo 的具体实现里，就应该写得更具体：

```text
v_\theta(s) ≈ v^{p_\rho}(s)
```

也就是说，AlphaGo 训练出的价值网络直接拟合的是 RL policy `p_\rho` 后续自我对弈下的胜负期望。

而论文希望由于 `p_\rho` 已经很强，所以：

```text
v^{p_\rho}(s) ≈ v^*(s)
```

于是价值网络也可以作为 `v^*(s)` 的近似信号被 MCTS 使用。

因此可以这样记：

```text
v(s)：泛称，一个局面价值函数，需看上下文。
v^p(s)：指定策略 p 后的真实期望价值。
v^*(s)：完美下棋下的最优价值。
v_\theta(s)：神经网络学出来的近似价值。
```

在严谨表达中，最好少单独写 `v(s)`，而是明确写 `v^p(s)`、`v^*(s)` 或 `v_\theta(s)`。

### 82. 第 47 页 phi 是否是特征函数

**问：** 47页，phi是一个特征函数？

**答：**

是的。这里的：

```text
\phi(s,a)
```

更准确地说是一个特征函数，或者特征向量映射。

它把“局面 `s` + 候选动作 `a`”映射成一个特征向量：

```text
\phi(s,a) = 局面-动作特征向量
```

这个向量里的每一维可以理解为一个局部判断，例如：

```text
候选点附近是否匹配某个 3x3 模式；
上一手附近是否有某种 response pattern；
候选落子附近棋子的颜色、气数、局部规则特征等。
```

rollout policy 的公式：

```text
p_\pi(a|s)= exp(π · φ(s,a)) / Σ_b exp(π · φ(s,b))
```

可以理解为：

```text
先用 \phi(s,a) 把每个候选落子变成特征向量；
再用参数 π 给这些特征加权打分；
最后通过 softmax 变成动作概率。
```

其中：

```text
\phi(s,a)：固定的人工特征函数
π：需要训练的权重参数
```



### 86. 输入特征表中的“平面”是什么意思

**问：** 这里平面是什么意思？

**答：**

这里的“平面”指的是 CNN 输入中的一个 `19x19` 特征通道。

围棋棋盘本身是 `19x19`。AlphaGo 不只是把棋盘做成一张黑白图，而是为每一种特征都准备一个或多个 `19x19` 矩阵。每个矩阵和棋盘位置一一对应：

```text
一个平面 = 一个 19x19 的特征图
一个格点的值 = 这个棋盘交叉点是否具有某种特征
多个平面叠起来 = 19x19xN 的神经网络输入
```

可以类比彩色图像：

```text
普通 RGB 图片：宽 x 高 x 3 个颜色通道
AlphaGo 输入：19 x 19 x 48 个围棋特征通道
```

例如“棋子颜色”有 3 个平面：

```text
平面 1：这个点是否有我方棋子
平面 2：这个点是否有对方棋子
平面 3：这个点是否为空点
```

“气数”有 8 个平面：

```text
平面 1：这个点所属棋串是否有 1 口气
平面 2：这个点所属棋串是否有 2 口气
...
平面 8：这个点所属棋串是否有 >=8 口气
```

所以“平面数 8”不是说有 8 张棋盘，而是说这个特征被 one-hot 编码成 8 个 `19x19` 通道。

总结：

```text
平面 = 19x19 的特征通道；
平面数 = 这个特征用了多少个通道来编码；
所有平面堆叠起来，就是 policy/value network 的输入张量。
```

### 90. 第 6 页 policy 是排序还是抽样

**问：** slide的第6页，减少宽度，用策略给候选动作排序。这个应该不是排序而是用于抽样吧？

**答：**

你的判断是对的，但需要分场景说得更精确。

策略 `p(a|s)` 的本质不是“排序器”，而是一个动作概率分布：

```text
p(a|s) = 在局面 s 下选择动作 a 的概率
```

这个概率分布可以有不同用法：

```text
自我对弈 / rollout：可以按 p(a|s) 抽样动作；
MCTS 搜索：可以把 p(a|s) 作为动作先验 P(s,a)，指导搜索优先探索高概率候选；
解释层面：概率越高的动作越值得先看，因此有时会说“排序”或“优先级”。
```

所以第 6 页写“给候选动作排序”有点窄。更准确的说法是：

```text
不平等考虑所有合法落子，而是用策略给候选动作分配概率；
这些概率可用于抽样，也可作为搜索先验，让搜索优先探索高概率候选。
```

已修改 `alphago.tex` 第 6 页，把“排序”改成“分配概率”，并补充：

```text
p(a|s) 可用于抽样，也可作为搜索先验。
policy network 的作用是让搜索优先探索高概率候选，降低有效分支因子 b。
```

### 91. 第 22 页 loss 是否意味着价值函数取值离散

**问：** 第22页，这个loss意味着价值函数的取值就是{-1,0,1}?

**答：**

不是。

这个 loss：

```text
loss = (z - v_\theta(s))^2
```

表示用终局胜负标签 `z` 去监督价值网络输出 `v_\theta(s)`。其中 `z` 是训练标签，通常是离散的终局结果。

在原始 AlphaGo 的围棋设定里，常用：

```text
z = +1：当前行棋方最终赢
z = -1：当前行棋方最终输
```

围棋通常通过贴目避免和棋，所以一般不是 `{ -1, 0, 1 }`，而是 `{ -1, +1 }`。如果某些游戏允许和棋，才可能把和棋记成 `0`。

但价值网络输出：

```text
v_\theta(s)
```

不是离散标签，而是一个连续数值。它近似的是期望胜负：

```text
v^{p_\rho}(s) = E[z | s, 后续按 p_\rho 下棋]
```

因此它可以取 `-1` 到 `+1` 之间的连续值。比如：

```text
v_\theta(s) = 0.6
```

可以理解为这个局面对当前行棋方比较有利，但还不是必胜。

如果没有和棋，并把胜负记为 `+1/-1`，那么：

```text
E[z] = P(win) - P(loss) = 2P(win) - 1
```

所以 `v_\theta(s)` 也可以和胜率互相换算：

```text
P(win) = (v_\theta(s) + 1) / 2
```

已在 `alphago.tex` 第 22 页 loss 公式下补充说明：

```text
z 是终局胜负标签；v_\theta(s) 是连续的期望价值估计，不是只能取离散值。
```

### 93. 强化学习自我对弈是否使用 MCTS

**问：** 强化学习自我对弈时，是采用MCTS还是直接抽样？

**答：**

在原始 AlphaGo 2016 论文里，训练强化学习策略网络 `p_\rho` 时，**自我对弈不是用 MCTS，而是直接按策略网络采样落子**。

也就是：

```text
当前网络 p_\rho
vs
历史版本网络 p_{\rho^-}
```

每一步从对应策略的概率分布中采样：

```text
a_t ~ p_\rho(\cdot | s_t)
```

然后用整盘棋最终胜负 `z_t` 做 policy gradient 更新：

```text
\Delta \rho \propto
\frac{\partial \log p_\rho(a_t|s_t)}{\partial \rho} z_t
```

所以这里的“自我对弈强化学习”是：

```text
直接策略采样 -> 得到胜负 -> REINFORCE 更新参数
```

不是：

```text
每一步先跑 MCTS -> 用搜索结果训练策略
```

MCTS 在原始 AlphaGo 中主要用于最终实战搜索。训练管线关系可以概括为：

```text
1. 用人类棋谱训练 SL policy p_\sigma
2. 从 p_\sigma 初始化，直接采样自我对弈训练 RL policy p_\rho
3. 用 p_\rho 自我对弈数据训练 value network v_\theta
4. 实战时用 MCTS 综合 p_\sigma、v_\theta 和 rollout
```

这个点和 AlphaGo Zero / AlphaZero 不同。后来的 Zero/AlphaZero 在自我对弈时会使用 MCTS，并把 MCTS 的访问次数分布作为策略训练目标；原始 AlphaGo 的 RL policy 训练不是这样。

### 95. 第 24 页 RL policy rollout 的含义

**问：** 第24页，RL policy rollout 是对RL policy 网络的前向推理么？

**答：**

可以这样理解，但要更准确一点：

```text
RL policy rollout 不是一次前向推理，
而是反复调用 RL policy network，按它的策略把棋从当前局面下到终局。
```

也就是说，从某个局面 `s` 开始：

```text
1. 对当前局面做一次前向推理，得到 p_\rho(\cdot | s)
2. 按这个分布选一步 a
3. 更新棋盘到下一个局面
4. 再对新局面做一次前向推理
5. 如此重复，直到终局
6. 得到最终胜负 z
```

所以：

```text
一次 p_\rho 前向推理：只给当前局面的下一步概率分布。
一次 RL policy rollout：需要很多次 p_\rho 前向推理，直到整盘棋结束。
```

第 24 页那句话：

```text
单次 v_\theta(s) 评估接近使用 RL policy rollout 的准确度，
但计算量少约 15000 倍。
```

意思是：

```text
value network 只做一次前向推理，就能直接估计局面价值；
RL policy rollout 要用深度策略网络一步一步下到终局，因此非常慢。
```

这也是为什么原始 AlphaGo 的实际 MCTS rollout 没有用深度 RL policy `p_\rho` 来模拟到终局，而是用一个弱很多但极快的 fast rollout policy `p_\pi`。

### 96. policy network 和 value network 一次推理的区别

**问：** 所以不论RL policy还是SL policy，一次推理都只能得到下一步的落点。于是看到终局必须一步步推理到终局。而价值网络从当前局面可以一步推理给出终局胜负的期望？

**答：**

是的，这个理解基本正确，但要稍微修正一句：

```text
policy network 一次推理不是直接“得到一个落点”，
而是得到下一步所有候选落点的概率分布。
```

例如：

```text
p_\sigma(a|s)：SL policy 对下一步落点的概率分布
p_\rho(a|s)：RL policy 对下一步落点的概率分布
```

如果真的要把棋局从当前局面下到终局，就必须反复做：

```text
当前局面 s
-> policy network 前向推理，得到 p(a|s)
-> 按概率采样或选一个动作 a
-> 更新棋盘
-> 对新局面继续前向推理
-> ...
-> 直到终局
```

所以 policy network 是“下一步模型”，不是“一步看到终局”的模型。

value network 不同。它一次前向推理输出一个标量：

```text
v_\theta(s)
```

这个数不是下一步落点，而是从当前行棋方视角对最终胜负的期望估计。原始 AlphaGo 中更准确地说：

```text
v_\theta(s) ≈ v^{p_\rho}(s)
```

也就是近似“如果从局面 `s` 开始，后续双方按强策略 `p_\rho` 下，当前行棋方最终胜负的期望”。

因此可以这样对比：

```text
policy network：
  输入当前局面；
  输出下一步动作概率分布；
  要看到终局，需要一步步 rollout。

value network：
  输入当前局面；
  输出终局胜负的期望估计；
  不需要真的模拟到终局。
```

但要注意，value network 给的是预测/近似，不是通过真实搜索保证出来的最终结果。

### 98. 实际 MCTS 是否采用 fast rollout

**问：** 实际MCTS在落子考虑的时候是采用fast rollout?

**答：**

原始 AlphaGo 的实际 MCTS 中，**会使用 fast rollout，但它只是 MCTS 的一个组成部分，不是全部**。

一次 MCTS 模拟大致分四步：

```text
1. Selection
   从根节点开始，根据 Q(s,a) + u(s,a) 选择路径。
   这里用到：
   P(s,a)：policy network 给的先验
   Q(s,a)：已有搜索统计得到的价值
   N(s,a)：访问次数

2. Expansion
   到达搜索树边界后，扩展新节点。
   新节点的动作先验 P(s,a) 来自 SL policy p_\sigma。

3. Evaluation
   评估叶节点 s_L。
   原始 AlphaGo 同时使用两种信号：
   value network：v_\theta(s_L)
   fast rollout policy：从 s_L 快速模拟到终局，得到 z_L

4. Backup
   把评估结果回传，更新路径上的 N、W、Q。
```

所以准确说：

```text
fast rollout 用在 MCTS 的叶节点评估阶段；
不是用来直接决定根节点下一手；
最终落子由根节点访问次数 N(s_0,a) 决定。
```

原始 AlphaGo 之所以不用 RL policy `p_\rho` 做 rollout，是因为深度网络太慢。一次 rollout 要从叶节点一步步下到终局，如果每一步都调用深度 CNN，计算量非常大。因此实际 rollout 使用的是弱很多但极快的：

```text
fast rollout policy p_\pi
```

可以压缩成一句话：

```text
原始 AlphaGo 的 MCTS 用 SL policy 提供搜索先验，
用 value network + fast rollout 评估叶节点，
最后按访问次数选择落子。
```

后来的 AlphaGo Zero / AlphaZero 去掉了 fast rollout，只用神经网络 value/policy 加 MCTS。

### 99. MCTS 搜索树什么时候扩展宽度

**问：** 按照目前的MCST描述，这个搜索树只会增加高度，什么时候扩展宽度？

**答：**

这里应该写作 `MCTS`。你的疑问很关键：如果只看“一次模拟”，MCTS 确实像是在沿一条路径往下走，因此看起来只增加高度。但完整 MCTS 是很多次模拟累积出来的，宽度是在多次模拟中逐渐展开的。

可以分两层理解。

**1. 一次模拟主要沿一条路径增加深度**

一次 MCTS simulation 通常是：

```text
从根节点出发
-> 在每个已展开节点选择一个动作
-> 沿一条路径走到当前搜索树边界
-> 评估叶节点
-> 回传更新统计量
```

所以单次模拟确实只访问一条路径。它更像是在回答：

```text
这一次我要深入检查哪一条候选变化？
```

**2. 宽度来自不同模拟选择不同分支**

下一次模拟不一定还走同一条路径。Selection 使用：

```text
Q(s,a) + u(s,a)
```

其中 `u(s,a)` 会鼓励探索访问少但先验概率高的动作。因此，在根节点或中间节点，MCTS 可能会改选另一个动作：

```text
第 1 次模拟：s -> a1 -> ...
第 2 次模拟：s -> a1 -> ...
第 3 次模拟：s -> a2 -> ...
第 4 次模拟：s -> a3 -> ...
```

当不同动作被选择并进一步访问、扩展时，同一层下就出现更多子分支，这就是搜索树宽度的增加。

所以：

```text
高度：某次模拟沿一条路径向更深处走。
宽度：多次模拟在某个节点选择不同动作，逐步激活更多子分支。
```

**3. 在 AlphaGo 的实现里还有“边”和“节点”的区别**

当一个局面 `s` 被加入搜索树时，通常会为它的合法动作建立边统计量：

```text
(s,a)：保存 P(s,a), N(s,a), Q(s,a) 等
```

但不是每条边的后继局面都会立刻作为完整节点继续展开。AlphaGo 的 METHODS 中有访问阈值思想：某条边被访问到一定程度后，才把后继状态加入搜索树并进一步展开。

因此可以区分：

```text
候选宽度：
  一个节点下有很多合法动作，policy 给它们 P(s,a) 先验。

实际展开宽度：
  MCTS 只把其中一部分被反复选中的动作扩展成后继节点。
```

这就是为什么 policy network 能“减少宽度”：不是删除其他合法动作，而是让 MCTS 优先把计算量分配给更有希望的少数分支。

一句话总结：

```text
MCTS 的一次模拟通常增加一条路径的深度；
MCTS 的多次模拟会在同一层探索不同动作，从而增加搜索树宽度。
```

### 100. 可尝试落点是否限于已激活节点

**问：** 所以可尝试的落点并不限于已经激活的节点？

**答：**

对。可尝试的落点不应理解为只限于“已经激活的节点”。这里要区分三层：

```text
1. 合法动作 / 可尝试落点
2. 搜索树中的边 (s,a)
3. 已扩展成完整节点的后继局面 s' = f(s,a)
```

在一个局面 `s` 下，围棋规则先给出所有合法落点：

```text
A(s)
```

这些都是理论上可尝试的动作。

当 `s` 被加入 MCTS 搜索树后，AlphaGo 会用 policy network 给这些合法动作先验：

```text
P(s,a) = p_\sigma(a|s)
```

并为这些动作维护边统计量，例如：

```text
N(s,a), Q(s,a), P(s,a)
```

但这不等于每个动作的后继局面都已经被展开成搜索树节点。

可以这样理解：

```text
边 (s,a) 已经存在：
  MCTS 知道在 s 下有这个候选落点 a，
  并且可以选择它、统计它。

后继节点 s' 已经扩展：
  MCTS 已经真正走过 a，
  把落子后的新局面 s' 加入搜索树，
  并准备继续从 s' 往下搜索。
```

所以某个落点可以处于几种状态：

```text
合法但还没被 MCTS 关注；
已有先验和边统计，但后继局面还没展开；
已经被访问并扩展成后继节点；
被多次访问，下面又继续长出更深的子树。
```

因此答案是：

```text
可尝试落点来自当前局面的合法动作集合 A(s)，不只限于已扩展节点。
MCTS 实际会优先尝试那些 policy 先验高、访问少或价值好的动作。
```

这也解释了“扩展宽度”怎么发生：当 selection 在某个节点选择了一个以前没怎么走过的动作 `a`，这个动作对应的后继局面就可能被加入搜索树，成为新的已扩展节点。

### 101. 进入未激活路径是否等于遇到叶节点

**问：** 如果进入一条还未激活的路径，那相当于已经遇到一个叶子节点了？

**答：**

基本可以这么理解，但要更精确地说：

```text
当 selection 在某个已在树中的局面 s，
选择了一个还没有扩展出后继节点的动作 a，
MCTS 就到达了当前搜索树的边界。
```

此时可以认为：

```text
s --a--> s'
```

这里的新局面 `s' = f(s,a)` 就是本次模拟遇到的叶节点，或者说新叶节点。

注意，“叶节点”不是围棋终局，而是：

```text
当前 MCTS 搜索树已经展开到的边界。
```

所以叶节点可能是：

```text
棋局还远没结束；
只是搜索树暂时还没有继续展开它。
```

一次模拟中的逻辑可以写成：

```text
1. 从根节点开始，在已扩展树内做 selection。
2. 如果选择到一条尚未扩展后继节点的边 (s,a)，就到达边界。
3. 生成后继局面 s' = f(s,a)。
4. 把 s' 当作叶节点进行 evaluation。
5. 必要时把 s' 加入搜索树，形成 expansion。
6. 将评估值 backup 回路径上的边。
```

因此你的说法是对的：

```text
进入还未激活的路径，
本质上就是走到了当前搜索树的叶子/边界。
```

只是更严谨地讲，未激活的是“后继节点还没展开”，而不是这个落点本身完全不存在；这个落点可能已经作为候选边 `(s,a)` 存在并有先验 `P(s,a)`。
